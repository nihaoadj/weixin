# 09. 交付、部署与运维

## 1. 环境策略

| 环境 | 用途 | 数据 | 模型 |
| --- | --- | --- | --- |
| local/mock | 纯逻辑、页面和单测 | 合成 fixture | mock |
| dev | 开发联调 | 可重置样例 | 低预算测试配置 |
| staging | 发布候选、迁移、E2E、压测 | 合成且接近生产规模 | 与生产同策略的受控账号 |
| prod | 正式/试点 | 真实数据 | 已审批模型和预算 |

每个环境使用独立 CloudBase 环境、数据库、存储、函数、密钥和告警。禁止用变量切换后在同一数据库混放环境数据。

## 2. 版本与分支

- 主分支始终可发布；功能使用短分支和 Pull Request；
- 语义化应用版本 + 独立 schema/migration 版本；
- 每次发布记录小程序版本、Git commit、云函数制品哈希、数据库迁移、模型配置、提示词和知识库版本；
- 紧急修复从当前生产 tag 创建，修复后合回主分支；
- ADR 记录跨模块或难以逆转的技术决策。

## 3. CI 流水线

```mermaid
flowchart LR
    PR["Pull Request"] --> STATIC["format/lint/typecheck"]
    STATIC --> TEST["unit/contract"]
    TEST --> SEC["secret/SAST/dependency"]
    SEC --> BUILD["小程序+云函数构建"]
    BUILD --> INT["staging integration/E2E"]
    INT --> AI["AI/医学回归"]
    AI --> APPROVE["产品+医学+安全审批"]
    APPROVE --> CANARY["灰度发布"]
    CANARY --> PROD["逐步放量"]
```

### 3.1 PR 阶段

- `npm ci`，验证 lockfile 未漂移；
- 格式、Lint、TypeScript `--noEmit`；
- 单元和契约测试；
- secret scan、依赖漏洞和许可证检查；
- 检查路由目标、组件 JSON、资源引用；
- 构建小程序与所有云函数；
- 变更数据库 schema/API/模型策略时要求对应文档和迁移。

### 3.2 发布阶段

- 从不可变 commit 构建一次制品，环境间推广同一制品；
- 注入服务端环境配置，不重新修改源码；
- 迁移先 dry-run、备份、执行、校验；
- staging 冒烟与核心 E2E；
- 发布审批记录责任人；
- 小比例灰度，观察错误、延迟、安全和业务指标后逐步扩大。

## 4. 数据库迁移

每个迁移包含：

```text
migration id
description
preconditions
up
verify
rollback/forward-fix plan
estimated duration
lock/traffic impact
owner
```

要求：

- migration 表记录版本、哈希、开始/结束、结果；
- 索引新增先在 staging 验证成本；
- 大数据回填采用批次、游标、限速和断点续跑；
- 破坏性变更使用 expand → migrate → contract：先兼容新旧字段，回填后再移除旧字段；
- 云函数回滚期间数据库 schema 仍兼容上一版本。

## 5. 配置与密钥

- 配置 schema 校验：缺关键变量启动失败；
- `dev/staging/prod` 密钥完全隔离；
- 密钥只有对应 Gateway/函数运行身份可读；
- 轮换不需要重新发布客户端；
- 记录密钥 owner、用途、创建、轮换和到期，不记录值；
- 客户端允许的配置仅包含环境标识、功能开关和公开版本号；
- 生产构建脚本扫描 API key、Bearer、测试用户、开发环境 ID 和真实健康文本。

## 6. 灰度与功能开关

功能开关适用于：

- 新模型/提示词/知识库；
- 新报告 schema；
- 流式响应；
- 新题型；
- 新安全策略（安全下限不可被普通开关关闭）。

开关按环境、组织、课程、用户百分比生效，带 owner、原因和过期时间。权限校验不能只依赖客户端开关。

灰度顺序建议：内部测试账号 → 医学审核团队 → 单个试点班级 → 多班级 → 全量。每一步定义观察窗口和自动回滚阈值。

## 7. 可观测性

### 7.1 结构化日志

统一字段：

```json
{
  "timestamp": "...",
  "level": "info",
  "service": "conversation",
  "environment": "prod",
  "requestId": "req_...",
  "actorIdHash": "...",
  "action": "messageSend",
  "resourceId": "conv_...",
  "outcome": "success",
  "latencyMs": 1200,
  "errorCode": null
}
```

禁止日志：完整消息、密钥、session、openid 明文、身份证/手机号、模型原始敏感请求。

### 7.2 指标

| 类别 | 指标 |
| --- | --- |
| API | 请求量、成功率、P50/P95/P99、错误码、冷启动、超时 |
| 数据库 | 读写量、慢查询、索引命中、冲突、事务失败、容量 |
| AI | provider/model、成功率、首响应/总延迟、token、费用、schema 失败、降级 |
| 安全 | 认证失败、越权拒绝、限流、注入命中、紧急风险、敏感访问 |
| 业务 | 作业可见率、开始/完成/提交/批阅漏斗、重复提交、等待批阅时长 |
| 客户端 | 页面错误、请求失败、白屏、版本分布、机型/基础库 |

### 7.3 告警

至少配置：

- 核心 API 5 分钟错误率/延迟超阈值；
- AI 费用或 token 异常增长；
- schema 失败、安全拒绝或紧急风险突增；
- 跨 scope/权限拒绝异常模式；
- 数据库容量、备份失败、迁移失败；
- 删除/保留任务失败；
- 凭证即将到期或供应商异常。

每个告警有 owner、严重级别、值班渠道和 runbook；无行动的噪声告警应调整。

## 8. SLO 与错误预算

建议为“登录/获取作业/保存消息/提交/批阅”分别定义可用性和延迟 SLO。AI 生成是外部依赖，区分：

- 请求被安全接受并保存；
- 模型生成成功；
- 完整报告在目标时间内可用。

当月错误预算耗尽时，暂停高风险功能发布，优先可靠性和根因修复。不要用客户端“显示成功”掩盖服务端未落库。

## 9. 备份与恢复

- 数据库自动备份 + 关键发布前手动恢复点；
- 对象存储版本/生命周期策略；
- 配置、提示词、知识库和 migration 进入版本库/制品库；
- 备份加密、访问隔离并遵循相同数据保留；
- 至少季度恢复演练到隔离环境，校验记录数、关系、权限和应用启动；
- 记录真实 RPO/RTO，而非只确认“有备份”。

## 10. 回滚

回滚对象分别处理：

- 小程序客户端：审核发布存在时延，后端必须兼容前一客户端版本；
- 云函数：保留上一不可变制品并支持快速切流；
- 数据库：优先 forward fix，破坏性迁移必须有预案；
- 模型/提示词：配置开关一键恢复上一已评测组合；
- 知识库：切回上一只读版本；
- 安全策略：不得回滚到低于批准安全基线。

## 11. Runbook

至少编写：

- 登录失败/微信上下文异常；
- 数据库超时或连接耗尽；
- 模型供应商不可用/限流；
- AI 费用突增；
- 危险医学输出举报；
- 教师越权/账号被盗；
- 密钥泄露；
- 删除任务失败；
- 灰度回滚；
- 备份恢复。

每个 runbook 包含症状、仪表盘、确认步骤、止损、恢复、升级联系人和复盘要求。
