# 研讨后学习计划与学习资源说明

> 用途：供产品、教学与研发讨论现有设计及后续优化。本文描述当前代码中的主流程和数据结构；它不是医学内容规范，也不代表每份 AI 生成内容都已经过教师或专家审核。

## 项目简介

病理学 PBL 教学助手面向病理学课程学生和教师，提供课堂研讨、自主学习、病例推理训练、教师审阅与学习进度查看。学生围绕病例进行多轮讨论；完成研讨后，系统根据研讨目标与分析生成个人学习计划，学生依次学习资料、完成合成病例推理，并在条件满足后进行最终测试。教师可审阅课堂路线对应的测试并查看课堂学习结果。

产品端为微信小程序，前端使用 uni-app、Vue 3、TypeScript，后端使用 FastAPI 与 SQLAlchemy。本文重点说明“研讨完成 → 学习路线 → 学习资源 → 最终结果”这段学生学习体验。

## 一页理解当前流程

```text
完成四阶段研讨
  → 冻结本次研讨分析并创建个人学习路线与最终测试
  → 按顺序完成 1–3 个资料步骤
  → 完成 1 个 AI 合成病例（病理识别 → 机制解释 → 证据判断）
  → 满足开放条件后完成一份四选一最终测试
  → 查看成绩、逐题答案和解析
```

每次完成的研讨对应一份路线和一份最终测试。课堂和自主研讨都生成个人路线；学生看不到其他学生的诊断、回答或学习路线。

## 研讨如何形成学习计划

### 1. 输入依据

路线生成使用本次完成研讨时冻结的分析快照、研讨目标知识点，以及知识库中可追溯的公开资料来源。分析区分两类信号：

- **知识薄弱点**：学生尚未掌握或需要巩固的病理知识。
- **推理问题**：如证据引用、机制衔接、鉴别判断或结论依据方面的问题。

它们用于选择学习目标和组织学习内容，不直接作为考试分数。系统不会把研讨中的 AI 讲解当作学生掌握知识的证据。研讨消息本身有“探究引导 / 直接讲解”方式；完成快照固定本次研讨分析，完成后的私人续问不再改写路线依据。

### 2. 创建与生成

四阶段研讨完成时，服务端在同一事务中冻结分析并创建路线、测试的持久化对象。路线和测试随后独立生成，因此一方失败不会撤销已完成的研讨或另一方已成功生成的内容。学生可在学习页看到生成状态；失败时可以重试未成功部分，成功内容和进度保留。

路线内容生成后即可由学生本人使用，不等待教师审阅。课堂最终测试需由有权教师审阅并开放；自主研讨的测试由 AI 直接开放，并明确标记为未经教师审阅。

## 资源类型与内容格式

### A. 学习计划总览

总览页展示：

- 计划标题与来源（课堂研讨 / 自主研讨）；
- 目标知识点；
- 研讨分析摘要；
- 顺序步骤及进度；
- 当前可执行动作（继续读资料、继续病例、等待生成、等待教师、重试、开始测试或查看结果）；
- 最终测试题数、生成及审阅状态。

对学生公开的是本人可读的摘要和必要学习内容，不返回模型原始输出、教师内部备注、未开放测试的题目或答案，也不在教师端展开学生完整病例对话。

### B. 定向资料学习

每份路线生成 **1–3 个资料步骤**，按顺序排列。每个资料步骤面向一个或多个目标知识点，结构为：

| 字段                       | 含义                                               |
| -------------------------- | -------------------------------------------------- |
| 标题与位置                 | 路线中的显示名称和步骤序号                         |
| 目标知识点                 | 本步骤覆盖的目标，可对应相关研讨薄弱点             |
| AI 导读 `ai_guide`         | 告诉学生阅读时重点关注什么、如何联系研讨中的问题   |
| 分段讲解 `sections`        | 若干 `{title, text}`，把关键概念组织成可阅读的小节 |
| 学习要点 `learning_points` | 阅读后自我检查的要点清单                           |
| 来源 `sources`             | 来源标题、机构、版本及来源链接等可追溯元数据       |
| 阅读进度                   | 服务端累计的有效前台阅读时间与最近活动信息         |

路线生成结果是版本化的严格结构化 JSON（以下为字段轮廓；省略 UUID、状态、来源快照等服务端字段）：

```json
{
  "version": 1,
  "title": "路线标题",
  "goal_point_codes": ["目标知识点编码"],
  "learning_rationale": "这些步骤与研讨薄弱点之间的关系",
  "reading_steps": [
    {
      "stable_key": "稳定步骤标识",
      "target_point_codes": ["目标知识点编码"],
      "linked_findings": ["关联的研讨发现标识"],
      "source_ids": ["允许使用的来源标识"],
      "ai_guide": "建议学生关注的阅读线索",
      "explanation_segments": ["小节讲解内容"],
      "learning_points": ["阅读后应能解释的要点"]
    }
  ],
  "synthetic_case": {
    "stable_key": "稳定病例标识",
    "title": "病例标题",
    "public_scenario": "公开病例情境",
    "target_point_codes": ["目标知识点编码"],
    "case_facts": [{ "fact_id": "事实标识", "text": "病例事实" }],
    "phases": [
      {
        "phase": "pathology_recognition",
        "goals": [
          {
            "goal_id": "阶段目标标识",
            "objective": "学生可见的阶段目标",
            "completion_requirements": ["服务端用于判断完成的要求"],
            "guidance_prompts": ["阶段引导提示"]
          }
        ]
      }
    ]
  },
  "safety_status": "educational"
}
```

实际病例要求固定包含三个阶段，并按病理识别、机制解释、证据判断排序；每阶段有 1–3 个目标，每个目标包含完成要求和提示。`safety_status` 只能是 `educational` 或 `needs_human_help`。服务端校验目标、来源、步骤键和阶段顺序后才保存供学生使用。学生端读取的是经过筛选的资料、病例公开情境、事实、当前阶段目标和提示，不读取服务端完成规则。

单个资料步骤字段示意（概念轮廓）：

```json
{
  "title": "资料步骤标题",
  "target_point_codes": ["目标知识点编码"],
  "source_ids": ["知识库中允许使用的来源标识"],
  "ai_guide": "建议学生关注的阅读线索",
  "explanation_segments": ["小节讲解内容"],
  "learning_points": ["阅读后应能解释的要点"]
}
```

来源由服务端从已允许的知识库来源中映射；模型不能自行编造来源 URL。讲解是路线中的教学内容，不等于来源原文、公共资源发布或专家签署意见。界面呈现为“学习提示 → 分段内容 → 资料来源 → 完成后检查”。

学生进入资料页后，系统在页面前台期间以心跳方式累计阅读时长；离开页面会暂停计时。**没有最低阅读时长**，学生阅读后点击“完成资料学习”确认完成，随后解锁下一步。时间用于学习过程记录，不用于评分或判定是否掌握。

### C. AI 合成病例

每份路线包含 **1 个合成病例**，安排在资料步骤之后。合成病例并非原课堂隐藏病例，也不是独立结构化病例库中的正式病例。公开给学生的结构包括：

| 字段                  | 含义                                         |
| --------------------- | -------------------------------------------- |
| 标题、公开情境        | 病例学习的背景描述                           |
| 病例事实 `case_facts` | 学生可以用于分析的病例信息                   |
| 目标知识点            | 与路线目标对应的知识范围                     |
| 当前阶段目标          | 当前阶段要完成的推理任务                     |
| 对话记录              | 本人提交的回答及 AI 导师回复，按修订序号排列 |
| 下一提示与安全提示    | 下一步引导及教育用途边界                     |

系统严格按以下三阶段推进：

1. **病理识别**：识别关键病理变化或主要问题。
2. **机制解释**：解释相关机制及其与表现之间的联系。
3. **证据判断**：结合病例证据作出判断并说明依据。

每阶段包含若干可解释的完成要求与提示。这些要求保存在服务端；学生看到的是阶段目标和对话提示，不会收到内部评分细则。学生在文本框输入分析后提交，AI 针对当前阶段回应。只有当前阶段证据满足要求时，服务端才允许进入下一阶段；每次最多前进一个阶段。证据不足时，系统说明缺少的要素，学生可以继续补充。三个阶段完成后病例步骤完成并返回计划页。

病例训练**不计分**，不设分数、等级或通过线，也不提供诊疗建议。病例中断或网络响应未确认时，页面显示待处理状态；系统通过同一请求身份恢复，不会自动重复发送或把未确认回复当作完成。

### D. 最终测试

每份路线对应 **唯一一份最终测试**，默认每个主要目标知识点生成三题；目标上限为三个，因此生成器最多输出九题。题目为四选一，单题结构包括：

```json
{
  "primary_point_code": "主要目标知识点编码",
  "prompt": "题干",
  "options": ["选项A", "选项B", "选项C", "选项D"],
  "correct_option": 0,
  "explanation": "答案解析",
  "source_ids": ["可追溯来源标识"]
}
```

AI 生成载荷还包含版本、稳定题目标识、关联研讨发现、来源标识和安全状态。`correct_option` 是从 0 开始的选项索引。学生端在测试开放前只会收到题干和四个选项，不会收到正确项、解析或教师审核备注；教师审阅端可查看并编辑题干、选项、正确项和解析。

**课堂路线：**教师审阅固定的研讨分析摘要和该生的测试草稿，可编辑、保存、要求修改或开放。学生可以先完成路线学习，再等待教师开放测试。测试开放后题目及版本冻结。

**自主路线：**AI 生成后直接开放测试，并标记为“AI 生成 / 未经教师审阅”；路线及成绩永久仅本人可见，不进入教师课堂统计。

学生开始测试后可选择答案并保存草稿，页面也会自动保存。提交前需完成全部题目并确认；提交后不可修改，整份测试只提交一次。评分由服务端确定性计算：正确题数 ÷ 总题数 × 100，保留一位小数并四舍五入。没有及格线；0 分仍是已完成结果。未提交时没有成绩，不以 0 分代替。

### E. 学习结果

提交后形成唯一学习结果，显示：

- 计划来源和标题、提交时间、最终得分；
- 答对题数与题目总数；
- 每题对应知识点、学生选择、正确选项和解析。

结果是本次路线最终测试的快照，不包含病例过程分，也不触发第二轮测试、补考或自动补强任务。课堂教师可查看有权限范围内已提交的课堂结果；自主结果只对学生本人可见。

### F. 与计划相邻的资源：知识点目录与独立病例

学习首页还提供知识点清单及知识地图。知识点详情可用于查阅课程知识材料、来源和知识关系；它是独立的内容入口，不是研讨完成后生成路线中的步骤，也不计入路线进度或最终测试成绩。

独立结构化病例训练保留独立入口，采用病史采集、问题表征、鉴别诊断、检查决策、初步处置五阶段。它与路线中的三阶段 AI 合成病例是两种不同资源；独立病例的正式评分按其自身规则执行，不并入本路线的最终测试结果。

## 学生操作路径

1. 学生完成课堂或自主 PBL 的四阶段研讨。
2. 打开“学习”页，在“研讨学习计划”卡片中查看自动创建的路线；也可以进入“全部计划”。
3. 打开计划详情，先查看目标、分析摘要、步骤顺序和当前行动。若路线或测试仍在后台生成，页面显示等待状态；只有失败的组件才提供重试。
4. 按顺序进入资料步骤，阅读导读、讲解与来源，完成自我检查并点击“完成资料学习”。
5. 进入 AI 合成病例，针对当前阶段提交文字回答，根据反馈补充证据，依次完成三个阶段。
6. 路线学习完成后：课堂学生等待教师开放测试；自主学生可直接开始已开放测试。若测试生成失败，可重试测试生成，不影响已完成的路线。
7. 回答所有单选题，确认并提交；之后查看总分、逐题作答与解析。

学生可返回路线详情查看已完成步骤。由于题目开放后冻结，刷新或重新进入可恢复测试草稿；已提交结果固定。

## 当前设计边界

- 一次完成的研讨只生成一条路线和一份最终测试；重新研讨产生新的路线，不是原路线补考。
- 资料阅读和 AI 病例是学习活动，不计分；最终测试是本路线唯一计分来源。
- 路线学习可先于课堂测试开放；所有锁定状态由服务端验证。
- 课堂数据按原课堂归属管理。离班或课堂归档后，不会把路线迁移到新班；已开放测试仍可由原学生继续完成，未开放测试不会因范围变化而新开放。
- 路线内容可供本人学习，但不因此变成公共资源或专家审核内容。教师审阅范围主要是课堂分析及最终测试。
- AI 生成内容使用严格结构校验；生成失败显式显示并支持有限重试，不以固定模板冒充个性化生成成功。

## 供讨论的优化问题

1. 资料步骤的数量、单步阅读负担和路线总时长是否适合课堂节奏？是否需要学生或教师控制学习节奏？
2. 当前依靠学生手动确认资料完成，是否需要增加自测、阅读理解检查或其他学习证据？若增加，如何避免把阅读时长误当成掌握程度？
3. 三阶段病例的目标和反馈，对不同基础学生是否足够清晰？学生是否需要查看阶段完成依据或回看前阶段？
4. 最终测试按每个目标三题生成，是否适合作为学习反馈？是否需要对题目难度、题型或反馈粒度作不同设计，同时保持路线结果可解释？
5. 课堂“先学习、后等教师开放测试”是否符合教学组织？教师端需要哪些审阅提示，才能在不暴露完整学生回答的情况下判断测试质量？
6. 自主路线标记为未经教师审阅是否足够醒目？学生应如何理解这类结果的用途与边界？
7. 当前知识点目录、路线资料、路线病例和独立病例入口之间是否容易区分？是否需要在导航和内容页解释它们的关系？
