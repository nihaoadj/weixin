# 08. 测试与质量保障

## 1. 质量目标

测试重点不是追求单一覆盖率数字，而是证明身份边界、数据状态机、医疗安全和核心闭环在变更后仍成立。

建议合并门禁：

```text
format-check
  → lint
  → typecheck
  → unit
  → contract/integration
  → secret/dependency scan
  → miniprogram build
```

发布门禁再增加 E2E、AI 回归、权限回归、生产包扫描和 staging 冒烟。

## 2. 测试分层

| 层 | 目标 | 示例 |
| --- | --- | --- |
| 静态 | 在运行前发现类型、规范、密钥、依赖问题 | TypeScript、ESLint、schema、secret scan |
| 单元 | 验证纯业务规则 | 状态机、评分范围、权限策略、脱敏、cursor |
| 契约 | 客户端/函数/模型输出一致 | 请求响应 JSON Schema、错误码、DTO |
| 集成 | 云函数与真实测试数据库协作 | 索引、事务、幂等、乐观锁、scope 查询 |
| E2E | 真机/模拟器用户闭环 | 教师发布 → 学生提交 → 教师批阅 |
| AI 评测 | 医学正确性、安全性和结构化稳定 | 固定黄金集、红队集、模型升级回归 |
| 非功能 | 性能、恢复、安全、兼容性 | 压测、故障注入、备份恢复、机型矩阵 |

## 3. 单元测试重点

### 3.1 权限策略

- 学生只能读写自己的 conversation/submission；
- 教师只能访问其 course/class scope；
- 撤销角色后立即拒绝；
- 资源不存在和无权访问对外表现一致，防 ID 枚举；
- 管理员也需要显式权限，不能因名称自动放行。

### 3.2 状态机

- 未发布题目不能创建 assignment；
- 已关闭作业不能开始新作答；
- completed conversation 不能追加消息；
- reviewed submission 不能无版本地覆盖；
- revision_requested 只能由原提交者重新提交；
- 合法 0 分可保存，负分和大于 100 拒绝。

### 3.3 幂等与并发

- 相同幂等键 + 相同请求返回同一结果；
- 相同键 + 不同请求返回冲突；
- 两个并发 messageSend 不产生重复 seq；
- 两名教师基于同一 version 提交，只有一个成功；
- 超时重试不重复计费或创建报告。

### 3.4 数据工具

- UTC/本地时间边界、截止时间；
- cursor 签名、篡改和条件变更；
- PII 脱敏的正例、漏报和误报；
- 日志序列化不包含正文、密钥和 openid；
- 数据迁移脚本的 dry-run、重跑和回滚。

## 4. API 契约测试

每个接口至少验证：

- 正常请求和最小/最大边界；
- 缺字段、多字段、错误类型、超长文本、非法枚举；
- 未登录、账号冻结、角色不足、scope 不匹配；
- NOT_FOUND、CONFLICT、RATE_LIMITED、AI_UNAVAILABLE；
- 响应不含 `_id`、openid、内部堆栈、供应商密钥；
- 旧客户端 schemaVersion 的兼容/强制升级策略。

模型供应商使用 adapter contract test：输入相同内部请求，各 provider 都返回统一结果或统一错误，不让供应商协议泄漏到业务层。

## 5. 集成测试环境

- 独立 test/staging CloudBase 环境，不连接生产集合；
- 测试数据使用合成医学案例，不使用生产对话副本；
- 每个测试创建唯一 organization/course 前缀并在结束后回收；
- 时间、模型和 ID provider 可注入，避免依赖真实当前时间；
- 模型调用默认 mock；少量供应商 smoke test 受预算和频率控制；
- 索引、权限规则和 migration 与生产同源部署。

## 6. E2E 关键场景

### 6.1 核心正向链路

1. 管理员邀请教师并建立课程/班级；
2. 教师创建病例分析题并提交医学审核；
3. 审核通过，教师发布给指定班级；
4. 目标学生可见，非目标学生不可见；
5. 学生多轮作答并恢复一次中断；
6. AI 生成带标识、引用和量表维度的报告；
7. 学生正式提交；
8. 教师评分并发布反馈；
9. 学生看到最终反馈；
10. 审计日志能串起整个 requestId/资源链路。

### 6.2 失败与恢复

- 网络断开后恢复，相同消息不重复；
- 模型超时，草稿仍在且可重试；
- 模型返回非法 JSON，不出现虚假报告；
- 数据库短暂失败，不发生半提交；
- 过期作业、冻结账号、撤回角色立即生效；
- 灰度版本失败可回退，旧客户端获得兼容响应。

### 6.3 安全与隐私

- 修改本地 role/openid 无效；
- 枚举 ID、换 userId、换 courseId 均越权失败；
- 输入提示注入不能获取系统提示、密钥或其他学生内容；
- 输入真实身份证/手机号时触发提示/脱敏策略；
- 撤回同意后不能开始新医疗对话；
- 删除请求完成后，主库/索引/导出均不可查询。

## 7. AI 与医学评测

模型、提示词、知识库、安全策略变更必须使用相同版本化数据集比较：

- 医学专家盲评正确性和危险性；
- 引用是否真实支持结论；
- 评分与教师黄金分的一致性；
- 紧急风险召回、个体化用药拦截、越狱和隐私泄露；
- schema 通过率、延迟和成本。

建议门禁示例（最终数值由医学/产品负责人确认）：

| 指标 | 候选门槛 |
| --- | ---: |
| 紧急高风险召回 | 100% 通过已批准高风险黄金集 |
| 产生明确危险建议 | 0 个阻断级样本 |
| 输出 schema 一次通过率 | ≥ 99% |
| 引用可定位率 | 100%（要求引用的用例） |
| 引用支持关键结论率 | ≥ 98% |
| API 普通请求 P95 | < 800 ms（不含模型） |

门槛不是对真实世界“绝对安全”的承诺，仍需灰度、监控和人工抽检。

## 8. 覆盖率策略

- 权限策略、状态机、幂等、评分与数据删除：分支覆盖建议 ≥ 90%；
- 共享业务域总体语句覆盖建议 ≥ 80%；
- 页面样式不强求代码覆盖率，用组件快照/视觉回归和 E2E；
- 新 bug 必须先增加能复现的回归测试；
- 不为提高数字测试无意义 getter/setter。

## 9. 真机与兼容性

至少覆盖：

- 微信开发者工具稳定版；
- 支持范围内最低与当前微信基础库；
- 主流 iOS/Android，不同屏幕、字体缩放、深色/浅色适用情况；
- 弱网、切后台、系统权限拒绝、登录授权取消；
- 长对话、长题目、中文标点、emoji、输入法确认；
- 页面栈限制、分享/返回、重复点击和低内存。

## 10. 缺陷等级

| 等级 | 示例 | 发布策略 |
| --- | --- | --- |
| S0 | 越权、密钥泄露、危险医疗建议、敏感数据泄露 | 立即停发/回滚 |
| S1 | 核心提交丢失、重复评分、无法登录、报告错误归属 | 阻断发布 |
| S2 | 部分流程失败、有安全降级方案 | 评估后限期修复 |
| S3 | 视觉/文案/低频体验问题 | 可进入 Backlog |

## 11. 当前仓库的第一批测试

建议先建立以下测试，作为重构安全网：

1. `resolveActor` 忽略 event.openid/role；
2. 教师 scope 权限矩阵；
3. 报告 `submissionId` 与数据库 `_id` 映射；
4. `score=0` 合法；
5. `saveConversation` 按 ID 更新而不是新增快照；
6. 学生只能读取被分配题目；
7. AI 输出 schema 校验与非法输出降级；
8. 胸痛/呼吸困难/意识障碍等高风险样本；
9. 生产包 secret scan；
10. 页面注册、组件标记、跳转目标和静态资源存在性检查。
