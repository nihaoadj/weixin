# 知识库维护与审核流程

## 修改原则

1. 先提出节点或边的医学问题，说明当前方向、拟改方向、机制和限制。
2. 至少登记可追溯来源；涉及分级、分期或具体疾病体系时优先使用对应权威指南，而非将总论关系外推。
3. 由病理学课程负责人或授权专家逐条确认。审核人、时间和状态必须写入节点/边记录；“有来源”不能代替专家签署。
4. 通过新的 Alembic 前向迁移发布新目录版本；不得手改生成的 OpenAPI、Demo JSON 或生产表。
5. 保持稳定知识点编码。确需退役时保存历史可解析映射，不重写既有证据、PBL 快照或任务记录。

## 必须验证

- 恰有一个 active catalog，模块、节点、材料、边和来源数量符合该版本清单；数量由版本迁移测试固定，不写成仓储的永久上限。
- 每个节点和每条边至少一个来源；被引用来源具备非空 key、标题、发布者、HTTPS URL 和合法访问日期。所有边端点存在、无自环、无重复、无有向环。
- 数据库边集合、`/knowledge/tree`、单点接口、Demo 快照和前端 `buildKnowledgeGraph` 的边集合完全一致。
- PBL provider 的 `allowed_points`、诊断校验、问答主题校验、证据指标校验和内容绑定均来自同一数据库目录。
- 聚焦树显示与当前模块相接的全部入向和出向跨模块前置摘要；全树不因排版过滤或重定向边；节点详情显示 rationale、limitation、confidence、来源和医学审核状态。
- 目录缺失、冲突或无效时显式失败，不回退到静态常量。

## 回退

`0028` 仅在目录仍为原始 v4 且没有审核人、审核时间或审核状态变化时允许降级。出现真实审核或后续编辑后，应通过前向修复迁移或已验证备份恢复，不破坏性降级。生产迁移前必须单独完成备份、演练、PostgreSQL 验证和医学审核。
