## 2. 已确定的页面设计

### 共同布局

- 使用白色卡片、浅冰蓝背景、深蓝标题和数字、青绿色强调色。顶部装饰保持较低高度，波纹背景浅淡，医学书本插画清晰。
- 三个页签使用同一浅色分段底座。选中项为青绿色渐变、白色加粗文字；未选中项为蓝灰色文字。底部保持现有 PBL / 学情 / 内容导航。
- 班级与课堂选择紧凑并排，支持全部课堂和单个课堂。三页共享筛选；切换班级清除原课堂选择，跨页签及“查看全部”保留当前范围。
- 全部课堂和单课堂复用相同组件与布局，只改变数据范围和实际行数。单课堂知识点较少时，卡片自然缩短。
- 参照真实手机比例和安全区适配。参考图中的手机外壳、状态栏、微信胶囊及系统手势条由真实设备或宿主提供，不在业务页面重复绘制。

### 总览

从上到下为三个区域：

1. **学习概况**：左侧完成率环形图，右侧平均分；下方设置共用的发布数量、完成数量统计条，数字加粗突出。统计名称和数量来源需按第 4 节修正。
2. **知识点作答表现**：紧凑表格展示少量知识点、客观题正确率和简答得分率。只显示百分比，不在百分比下显示正确数、总题数或得分分子分母。“查看全部”切换到知识与推理页。
3. **得分较低学生**：采用与学生页一致的紧凑两行样式。第一行是默认头像、姓名、平均分小徽标和详情箭头；第二行是测试完成比例与研讨完成/进行次数。保留“查看全部”进入学生页，学生行进入个人详情。

### 知识与推理

上方展示完整的知识点作答表格，下方展示课堂研讨诊断中的知识缺口和推理问题。保留已有真实诊断数据，但需要解决“汇总人数与具体诊断描述”的对应关系，不能固定写死图片中的两条描述。

单课堂按实际统计结果展示知识点，通常是一行；不将单个知识点放大成占据主体的大卡片，也不混入其他课堂的数据。

### 学生

使用统一白色紧凑列表与细分隔线，减少单人区域的高度。一屏约七名学生体现参考密度，实际人数按设备、字体及数据适配，并支持继续加载。

每人两行呈现：第一行姓名、区间平均分及详情箭头；第二行测试完成比例/完成率和研讨完成/进行次数。统一采用浅蓝圆形默认人形头像，分数使用小徽标，数据标签中的数字加粗。移除平均分旁的“样本 1 份”等说明。

## 3. 当前功能与可复用能力

当前源码已有班级、课堂和日期筛选，四个页签，学习完成率与平均分、知识点客观题及简答统计、课堂研讨进度、知识缺口/推理问题及去重学生人数。新设计主要重组这些能力。

已有学生详情与单份测试结果页面应保留入口，包括研讨阶段、学习步骤、阅读时间、测试结果、个人诊断以及逐题作答和评分反馈。主列表保持简洁，详细内容通过学生行进入后续页面；PBL 审阅和发布继续由原页面承担。

总览目前只读取概况接口。新增知识点预览与低分学生预览，需要规划复用查询或新增汇总的方式；“查看全部”、进度页签合并及历史入口兼容也需纳入实施。

## 4. 下一步规划必须明确的事项

| 事项               | 当前事实与规划要求                                                                                                                                                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发布数量与完成率   | 当前 `publishedRoutes` 统计已发布路线，完成率为该发布批次中已完成测试数除以路线数，并非已发布测试数。不得直接将其改名为“已发布测试”。规划师需确定修正文案，还是增加真实测试发布统计；后者同步明确分母和完成率。                                                |
| 共用统计条与平均分 | 发布批次完成情况截至查询时统计；平均分按区间内测试完成结果计算。两者的已完成数量不保证相同，共用统计条不能被当作平均分的样本数量。需明确展示文案及字段映射。                                                                                                   |
| 百分比计算         | 现有知识点正确率按有效题累计正确数/题数，简答得分率按累计得分/满分。去掉界面中的分子分母不改变计算方式，不擅自改成每名学生百分比的算术平均。                                                                                                                   |
| 诊断展示           | 当前人数按知识点或推理维度分组并去重，一组学生可能有不同问题。应展示明确的知识点/推理维度，并规划展开或详情查看各学生摘要；单人描述不能代表整组。                                                                                                              |
| 预览与颜色规则     | 图片的知识点、低分学生预览各三项可作为布局参考，但数量、排序、低分定义及颜色规则仍需确定。当前接口主要按编码/编号返回，不能只对第一页学生排序便宣称是全班最低分。无成绩学生不参与低分排名。                                                                    |
| 日期范围           | 当前默认最近 30 天，“全部课堂”也受日期限制。研讨次数按区间内开始参与的记录统计，测试成绩按测试完成时间、诊断按研讨完成记录筛选，各类统计不共用分母。主界面已去掉独立日期条；规划师需确定统计周期及日期筛选的承载方式，必要时收进筛选弹层，避免误认全历史汇总。 |
| 多班级详情         | 保留“全部授权班级”能力时，同一学生可能关联多个班级。点击详情必须明确班级上下文，必要时先选择班级，不能任意取一个班级。                                                                                                                                         |

## 5. 状态与范围约束

需要设计加载、失败重试、空数据、缺少对应题型和列表继续加载状态。无完成结果显示“暂无结果”；无有效分母显示“暂无样本”；真实零分保留为零。无诊断记录不编造薄弱点，无简答记录不显示为零分率。

主页面不恢复已删除的“判分中”、单独“进度”页签、“深入查看”独立导航块、示例数据标记和冗余说明条。详细学习进度与逐题作答通过已有详情入口保留。

## 6. 建议实施顺序与验收重点

先确定第 4 节的数据口径与交互决策，再形成页面/组件、接口、导航兼容和验收计划。涉及功能、数据或导航变化时，依照[开发流程](D:/CODE/weixin/wxprogrom7.15/docs/development.md)完成对应计划门禁。

实施顺序建议为：共用视觉与筛选组件 → 三页布局及进度合并 → 真实统计映射、预览与诊断交互 → 详情入口和边界状态 → Demo 同步及微信验收。

验收重点为真实手机上的主体展示空间与文字可读性、三个页签状态一致、全部/单课堂范围正确、跳转保留筛选、数据计算真实、无结果与零分区分、长列表可继续加载，以及已有学生详情和逐题作答仍可到达。图片比例和视觉接近不等于数据及功能验收通过。
