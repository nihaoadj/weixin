# 医学知识问答小程序完善文档

> 文档基线：2026-08-07。内容基于当前仓库源码的静态审计；未连接真实 CloudBase 环境，也未执行小程序端到端运行。

## 结论先行

这个项目已经具备学生问答、历史记录、报告、教师批阅、问题管理等页面雏形，但目前仍是 Demo，不能直接上线。核心原因不是页面数量不足，而是运行代码与 TypeScript 源码分叉、数据主要保存在本机、客户端直连大模型并暴露密钥、服务端信任客户端传来的身份，以及题库—作答—报告—批阅链路尚未形成统一的数据闭环。

推荐采用“渐进式完善”，不重写小程序：

| 层 | 推荐技术 | 选择理由 |
| --- | --- | --- |
| 客户端 | 原生微信小程序 + TypeScript 严格模式 + WXML/WXSS | 已有代码可复用；无需承担 Taro/uni-app 迁移成本 |
| 状态与请求 | 轻量 `services/` + `store/` 分层；运行时数据校验 | 项目规模尚不需要重型前端框架，但必须消除页面直接访问存储/API |
| MVP 后端 | CloudBase 云函数 + Node.js（使用平台当前支持的活跃 LTS） | 与现有微信登录、文档数据库、云存储衔接最短 |
| MVP 数据库 | CloudBase 文档数据库 | 快速完成课程、题目、对话、报告闭环 |
| 规模化后端 | CloudBase 云托管 + NestJS/Fastify + MySQL/TDSQL | 当需要复杂统计、强事务、开放 API 或稳定长连接时再升级 |
| AI 接入 | 服务端 AI Gateway + 已备案/可商用模型 + 结构化输出 + 安全策略 | 隐藏密钥、统一审计、限流、模型切换与医学安全控制 |
| 工程质量 | ESLint + Prettier + Vitest/Jest + 小程序自动化测试 + CI | 让类型检查、单测、安全扫描和构建成为合并门禁 |
| 观测 | 结构化日志 + requestId + 云函数指标 + 告警 + AI 质量看板 | 能定位失败、成本、延迟与模型质量回退 |

## 建议的实施顺序

1. 立即轮换已暴露的 AI 凭证，删除客户端直连大模型；禁止发布当前版本。
2. 统一 TypeScript 为唯一源码，恢复可重复安装和可通过的构建。
3. 服务端使用可信微信上下文识别用户，建立教师准入和 RBAC，禁止接收客户端自报的 `openid/role`。
4. 建立统一数据模型与云端仓储，先打通“教师发布题目 → 学生作答 → AI 报告 → 教师批阅”。
5. 加入医疗安全、隐私同意、数据删除/导出、审计日志和 AI 内容标识。
6. 补齐测试、灰度、监控、备份与回滚后，再进入试点。

详细的 12 周路线见[实施路线与优先级](./10-implementation-roadmap.md)。

## 完成标准

项目“完善”不应以“页面看起来完整”为标准，而应至少满足：

- 客户端不含任何服务端密钥，所有写操作在服务端鉴权；
- 不同账号、设备看到一致的云端数据，学生不能访问他人记录；
- 教师身份由管理员授予，所有批阅和发布行为可审计；
- AI 输出有显著标识、适用边界、紧急风险处置、引用/依据与人工反馈入口；
- 医疗健康数据有单独同意、最小化收集、可撤回、可删除和保留期限；
- 核心链路具备自动化测试、监控、告警、备份和可演练的回滚；
- 产品明确是“医学教育辅助”，不替代医生诊断、处方或急救服务。
