# 验证与回退

## 分阶段验证

- 计划：Scoped Prettier、相对链接、尾随空白、`git diff --check`、skill self-check。
- 状态机：逐级推进、新证据、越级/旧证据/提前 ready 拒绝、不可用不推进、并发重试、完成锁定。
- 自动判定：首轮全通过；知识再测、微训练、病例目标维度分别失败；高总分但目标维度不足仍失败。
- 第二轮：只激活失败目标、variant 不重复、通过/耗尽、重复提交与通知幂等。
- 权限隐私：跨班级拒绝、教师只读、学生隐藏 rubric/答案/提示/病例事实、日志最小化。
- 迁移转换：空库、0017、历史三类状态、dry-run/apply、带新数据 downgrade 拒绝。
- 前端：320–1440 宽度、H5/微信构建、API/Demo 合同一致，两条完整 UI E2E。

## 最终门禁

按风险执行契约生成与检查、数据库安全/迁移、后端完整检查、前后端边界、Lint、类型、单测、H5/微信构建、API/Demo E2E 和工作树秘密扫描。命令、时间、退出码和未执行项写入交付记录。

## 回退

- 回退前停止 PBL 消息、采用发布、任务提交和病例评估写入，生成并验证一致性备份。
- 没有 schema v3 阶段数据与 cycle 2 任务时可执行 0018 downgrade，再回退应用和生成合同。
- 已存在新业务数据时 downgrade 必须拒绝；只能部署兼容读版本或从已验证备份恢复，不得静默删列丢数据。
- 历史转换 apply 前保留备份与 dry-run 计数；恢复以一致性备份为准。
