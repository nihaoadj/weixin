# 数据转换

## 当前事实与待实现目标

默认开发 SQLite 位于 backend/data/dev.db，观察版本为 0007。代码 head 为 0016。用户授权备份后清理旧教学/学习链并重建病理示例，未授权操作其他现存数据库、生产、共享或远程资源。

## 执行协议

1. 工具显式接收数据库路径，默认 dry-run；拒绝目录、链接、越出 backend/data 的路径和 production 环境。读取规范路径、schema 版本和清理计数，不输出业务原文。
2. 使用 SQLite backup API 创建一致性备份（包含 WAL 中已提交数据），验证 integrity_check/foreign_key_check、schema 版本和保护表计数。保存内容摘要与转换 manifest 到忽略的 backend/data 下。
3. 从备份创建受管副本；先升级后继 schema，在副本清理/seed，检查恢复和重复执行幂等。
4. apply 前核对源指纹未变化并停止服务写入；备份后升级受管开发库，在事务内清理并建立新资源。失败回滚清理事务；schema 失败按备份恢复，不强行 stamp。

## 清理与保护规则

旧知识点使用二十四个明确编码集合；示例资源使用既有五种种子 slug/明确 client ID。删除旧 ReviewAttempt/State/Item、内科补充卡和知识关联。题目/病例以旧种子或仅旧知识关联识别，遇到 PBL origin 或其他病理关联必须保护。

依赖删除按通知、学习任务尝试、学习任务、计划、训练评估/提交/消息/尝试、普通题作答线程、审核记录、知识关联、旧示例题目顺序，并处理 retry/parent 外键。AI 日志只按确切关联资源清理。示例对话/报告按固定种子标识清理；非示例原始消息/报告保留，仅移除内科知识关联。账号、班级和 PBL 对象全部保护。

新病理知识以未开始状态建立，禁止复用旧分数或把旧病例原位改名成新病例。seed 采用新 slug 且幂等，不在生产自动建立演示审核状态。Demo 存储版本升级，仅按明确旧种子和内科编码转换，保留其他用户数据和失败原值。

## 回退

清理不嵌入 Alembic。downgrade 仅撤销新增 schema，不能恢复删除数据；完整恢复依赖转换前一致性备份。恢复前停止写入，验证备份归属、指纹及路径。交付记录备份位置与计数，但不提交数据库或敏感原文。
