# 产品流程

## 待实现目标

学生默认进入“我的 PBL 课堂”，导航依次为课堂、任务、知识、答疑、记录；病例从课堂/任务进入。教师默认 PBL，保留报告、内容、班级和学情入口。沿用 med 颜色、间距和字体令牌，以“知识—证据—任务”的顺序表达教学关系；桌面筛选/列表/详情，移动端列表到详情。

教师从本人可用、已发布且医学审核通过的病理病例建课。冻结病例 ID、版本、摘要和最多三个目标知识点。阶段为 problem_framing（明确问题）、hypothesis（提出假设）、evidence（讨论证据）、synthesis（总结解释）；课堂 active/closed 与教学阶段分开。旧课堂不补造绑定；关闭后参与者可以查看本人历史，不能新增参与或消息，课后任务继续。

学生问题进入 AI 追问，证据不足保持 probing/insufficient_evidence；ready 必须有合法知识/推理分析及学生消息证据。教师队列显示学生、班级、课堂、时间、状态、逐条依据；按班级/课堂/学生/处理状态筛选，20 条分页，默认每位参与学生最新有效诊断，详情显示历史。教师仅看最小必要摘要，不新增整段私人对话查看功能。

教师编辑后一次采用发布，默认目标为来源学生，可选同班其他学生/全班。原子保存文案、正式题、来源、任务、通知和建议状态。学生完成讨论及对应复习/微训练/再测，教师根据证据确认 improved（已改善）或 needs_work（需继续巩固）。AI 不自动发布、评分或确认改善。

加载、空、失败、版本冲突、重复操作均须提供可恢复交互。消息重试保留 client_message_id 和草稿；服务器消息序列是最终来源。刷新/切换课堂不得混入旧请求结果。不得在 API 失败后切换 Demo。
