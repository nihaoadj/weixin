# 实施任务

## 阶段一：固定学生导航与课堂层级

1. 将 PBL 页的 `StudentNav` 包装为固定底部导航壳，增加底部留白。
2. 补充课堂状态、阶段和学习线索的紧凑状态区域，复用已有 session/diagnostic 数据。
3. 与知识、学习、记录页的导航壳视觉一致，不改变主路由语义。

出口：学生在长对话、空课堂、课堂关闭和加载失败状态都能立即切换主入口，且输入框和导航互不遮挡。

## 阶段二：任务的下一步引导

1. 为每个 PBL 计划计算完成比例和第一项可执行任务。
2. 保留现有任务顺序、状态和提交 API；只优化视觉层级、按钮文案和状态反馈。
3. 为完成待核验、已改善和需巩固状态提供可扫描的状态标签。

出口：用户不需逐项阅读即可识别当前计划、下一步和教师核验状态。

## 阶段三：教师工作区切换

1. 将同页 tab 切换改为本地状态，保留深链接初始 tab 支持。
2. 用“首次访问挂载＋`v-show`”保留已访问工作区，保持可见组件的公开事件与 ref 行为，并保持微信小程序编译兼容。
3. 在切换后仅刷新需要刷新目标，防止快速重复点击。

出口：教师在 PBL、报告、问题、工作台之间切换不产生整页路由替换，且数据范围、发布权限与错误反馈不变。

## 阶段四：验证与交付

运行 scoped formatter、Lint、类型检查、相关 Vitest、前端边界检查、H5/微信构建和 API/Demo E2E。更新交付记录，不运行真实 AI。
