## 分步实施与验收

1. S0：前端、后端、旧脚本并行只读审计，记录删除/保留依据。计划格式/链接/空白与技能自检通过后实施。
2. S1：快照拟删文件；清理旧脚本、停用npm命令和仅供其使用的开发依赖，按原锁定版本维护package-lock，不升级其他包。无引用组件、测试专属用例及经核实的死代码/资源同步清理；保留混合测试有效覆盖。
3. S2：验证无残留活动引用、注册页面均存在、静态资源引用有效、类型/Lint/格式、前端边界与完整前端测试、Demo构建及原生模板/样式。涉及后端运行代码则增加受影响pytest/ruff/后端边界，受管fixture，不操作真实库。必要微信渲染按规则最小验证；无UI/数据行为改变则复用刚通过的当前页面证据，不能以清理声称重新验收全部交互。
4. S3：记录实际删除/保留清单、命令退出码与未验项，更新现行工具文档。按仅留最新两份计划规则归档T63并逐文件验证ZIP/hash，保留T64/T65；归档不免除旧待验，不重开已收尾阶段。
