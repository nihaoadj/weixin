# T06 安全、隐私与发布边界任务书

状态：待执行。优先级：历史凭据核查 P0，其余本地加固 P1。执行角色：熟悉 Web/API 安全的工程师；凭据平台与仓库管理员负责外部动作。

## 1. 目标与授权边界

确认并加固角色权限、病例隐藏数据、会话缓存、日志、AI 数据流、生产配置和供应链边界，留下可以复验的安全证据。安全 skill 可辅助审阅，但不得以“运行过 skill”代替具体断言或实际修复。

仓库内安全代码和测试可按本任务实施。真实密钥撤销/轮换、生产环境变量修改、远程历史重写、生产数据库变更、医学专家签署必须由获得明确授权的执行者/负责人完成。没有授权或访问能力时，先完成可完成的仓库工作，提供精确操作清单、影响与回退方案，再交管理员处理；不能要求用户在聊天中提供密钥。

不对真实学生/患者数据开展攻击实验，不将业务数据发送给外部扫描或模型服务，不擅自发布安全细节或通知第三方。

## 3. 分步实施

### T06-01 建立资产、信任边界与风险清单

记录客户端、API、数据库、微信身份服务、模型服务、CI、开发工具和 Demo 数据的边界。列出 token、账号映射、班级成员、学生答案、教师批阅、隐藏 rubric、模型凭据、审核 digest 等资产及允许流向。

给每项风险记录受影响入口、攻击前提、可观察影响、现有防护、缺口、优先级、负责模块和验收 ID。只把已证实问题标为漏洞；推测项记录需要验证的假设。

产出：仓库针对性的威胁模型与数据流图。不以通用 OWASP 清单替代项目证据，也不扩展成未经授权的渗透测试。

### T06-02 处理历史凭据并建立秘密扫描

先引用现有文档中的历史位置，不在报告、日志或聊天重现完整 key。通过平台管理员核实撤销/轮换时间、旧凭据状态及必要的调用审计；只记录脱敏标识和操作凭证。无法核实则保留 P0 发布阻塞，不将“工作树没有 key”视为完成。

引入锁定版本、可在 Windows/Linux/CI 使用的秘密扫描工具，提供 `security:secrets`。扫描受版本管理的源码、配置和新增差异，并对可取得的完整 Git 历史做一次脱敏审计；构建产物另做客户端泄露验证。扫描器使用合成样本自测，日志只显示位置、规则和脱敏指纹。

已撤销的历史秘密仍是历史发现，报告不能删除；是否重写历史由管理员评估协作者和镜像影响后单独决策。日常增量门禁允许精确区分已证实撤销的历史指纹与新泄露，但不得用整目录/整类 key 白名单忽略风险，也不得豁免仍有效或状态未知的秘密。

产出：脱敏泄露处置记录、扫描脚本/规则、自测、必要的管理员操作单。

### T06-03 固化权限矩阵并验证全部入口

使用下表作为最小起点，与当前产品规范及负责人确认最终政策；覆盖列表、摘要、详情、写入、克隆、审核、分析及旧兼容接口，不能只验证详情接口。

| 主体         | 可访问范围                                         | 必须拒绝的行为                                       |
| ------------ | -------------------------------------------------- | ---------------------------------------------------- |
| 未认证客户端 | 健康检查、合规登录入口及明确公开资源               | 私有业务数据、教师操作                               |
| 学生 A       | 自己的会话、报告、训练、计划、通知和对其公开的题目 | 学生 B 数据；hidden facts/rubric；任意教师或审核功能 |
| 教师 A       | 已定义范围内的班级、学生报告与内容管理             | 其他教师 owner 数据；未经授权获取审核权限            |
| 医学审核者   | 获授权的病例审核流程                               | 自动获得全部教师学情和班级数据                       |
| Demo 身份    | 明确非生产演示范围                                 | 冒用微信账号、客户端自授角色/permissions             |

检查服务端 actor、owner/member 和 auth_provider；前端隐藏按钮只能辅助交互，不是授权控制。服务端忽略或拒绝客户端伪造 owner、reviewer、role、permissions 等敏感字段。

产出：端点×角色矩阵、修复清单、对应 T05 AUTH/REPORT/CONTENT/CLASS 用例。必要的业务政策变更单独批准并反映到接口合同。

### T06-04 审核数据最小化、缓存与日志

对学生 DTO 使用明确字段结构，检查嵌套 JSON、摘要、错误响应和生成 fixture 均不泄漏隐藏事实、参考推理、评分 criteria、审核内部字段、定向对象 ID 或模型 prompt。

验证 API 业务响应不写入本地持久存储，token/身份变更清空缓存，旧请求不能回填新身份缓存；检查 logs 服务、console、后端异常、AI 审计与 CI 制品。不得记录 token、微信 session_key、AppSecret、完整答案/报告/消息或数据库 URL 凭据。

日志采用允许字段清单：路由、方法、状态、耗时、脱敏关联 ID、失败类别及批准的模型元数据。检查异常堆栈和第三方客户端 debug 日志，不能只过滤正常日志。

产出：字段/日志允许清单、脱敏回归、数据泄露负向测试。真实学生数据不得作为 fixture。

### T06-05 验证 AI、审核和教学安全边界

模型只能接收任务必要且去标识化的上下文；无关历史、身份和私密蓝图不送入外部模型。超时/错误/非法结构/注入输入应按现有合同有界重试并安全 fallback。

评分由服务端确定性 criteria 计算；审核 digest 对应当前内容版本；参考证据必须来自学生答案且符合现有条数和长度上限。审核后内容变化必须失效，Demo 审核不能宣称等价真实医学专家签署。

急症提示、处方/剂量限制和教学免责声明采用已批准规范；不在工程任务中凭空增加临床建议。软件校验通过只代表工程边界通过，不能替代医学内容审核或现实合规评估。

产出：AI 数据流、输入输出规则、审核一致性证据与外部医学审核检查单。

### T06-06 加固生产配置、依赖与构建输出

验证 APP_ENV=production 下弱/缺 JWT、Demo 登录、开发 seed、错误调试信息的处理；生产缺少必要配置应按明确策略拒绝相关功能或启动，不能静默以开发身份替代。核查生产 CORS、HTTPS、微信合法域名和服务端凭据位置。

依赖审计由 T02 运行，T06 对发现进行风险归属和修复验证；DCloud 版本批次与锁文件规则不放宽。客户端 H5/微信构建产物不得包含后端秘密、配置备份和真实数据。不要把 AppID 当作 AppSecret，也不要因 AppID 可公开就忽略服务端授权。

记录生产数据库选择、备份恢复和容量/并发风险。当前 PostgreSQL 尚未实测，不承诺只改 URL 就可上线，也不把生产迁库扩展进本任务。

### T06-07 完成安全验收和外部移交

针对已确认问题复验并关联代码、测试和证据。提交仓库内检查结果及外部发布清单，区分“代码加固完成”“凭据/平台事项完成”“允许生产发布”。

管理员收到的动作必须具体：目标平台与凭据类型、预期影响、执行/回退步骤、验证方法、仅需返回的脱敏证据。缺少权限时不可伪造已完成状态。

## 5. 验证方式与交付物

T01 安全环境和目标命令实现后执行：

```bash
npm run security:secrets
npm run audit:prod
npm run audit:all
npm run backend:audit
npm run test:critical
npm run backend:test:critical
npm run build:mp-weixin
npm run build:h5
```

构建泄露检查使用扫描器/专用断言验证，但不把构建目录提交仓库。真实模型或微信服务的集成验证使用管理员批准的测试账号与环境，和普通离线测试分开。

- [ ] 仓库内 SEC-02～SEC-08 全部通过，风险报告每项均有处理结论。
- [ ] SEC-01/09 未完成则明确状态，不能宣布发布安全闭环。
- [ ] 交付威胁与数据流图、权限/字段/日志矩阵、修复与测试、扫描规则、外部操作单和 `deliveries/T06.md`。
- [ ] 报告、日志、fixture、截图、交付物无真实凭据或敏感业务资料。

## 6. 回退策略

已泄露密钥撤销后不恢复原 key；新凭据配置失败应使用安全回退或暂停相关功能。安全缺陷修复回退需确认不会重新开放漏洞，必要时先禁用受影响入口。远程历史重写先留受控备份与协作者恢复方案，绝不由普通仓库代码任务顺手强推执行。
