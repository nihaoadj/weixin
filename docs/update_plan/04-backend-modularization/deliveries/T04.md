## 实现与责任边界

- 八个模块 `identity`、`qa`、`reports`、`content`、`training`、`learning`、`classroom`、`analytics` 均有真实的 `api/application/domain/infrastructure`，并有 `public.py` 与 `wiring.py`。生产 `app.main` 直接装配模块 router；旧 `app/api` 只作导入兼容 alias。
- 路由中的请求/响应 schema 已迁移到模块 `api/schemas.py`；`app/schemas/*` 只 re-export，未保留中央 Pydantic 定义。canonical SQLAlchemy 模型位于各模块 `infrastructure/models.py`；`app/models/*` 只 re-export。
- `app/bootstrap/model_registry.py` 是唯一 ORM metadata 注册汇合点，`app/db.py` 和 `alembic/env.py` 只通过它装配模型。`app/bootstrap/composition.py` 是跨模块 composition root；learning 依赖 `training.public.TrainingCasePort`，不导入 training application/use case。
- `app/services/*` 中仍存在的入口均为窄兼容 facade、mapper 或旧 seed 导出；它们不再承载生产状态机、SQL 业务编排、另一套评分实现或 seed 实现。开发/测试 seed 的实际拥有者是 `app/bootstrap/test_seed.py`，showcase seed 的实际拥有者是 `app/bootstrap/seed.py`。`training/infrastructure/legacy_hook.py` 已删除；生产 wiring 默认直接装配 `CaseAiGateway`，测试通过 `AssessmentGateway`/`PatientReplyGateway` 显式注入。
- `app/platform/transactions.py` 提供 request-scoped `SqlAlchemyUnitOfWork`；repository 只 query/add/flush/refresh，应用用例是唯一 commit/rollback 拥有者。Actor 是 HTTP 到 application 的唯一身份合同，应用层再次校验角色、owner、可见范围与状态。核心层只抛 `AppError`，HTTP 层映射既有错误码和响应字段。
- content 拥有 `problems`、`medical_reviews`；identity 拥有 `users`；qa 拥有 conversation/question 表；training 拥有 case attempt/assessment/audit 表；learning 拥有 plan/task/notification 表；classroom 拥有 class/member 表；analytics 只拥有只读 query adapter，不写业务表。跨模块 ORM 读取按 `config/backend-boundaries.json` 的逐路径 allowlist 记录。
