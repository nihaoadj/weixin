# 当前导航与标题审计

## 已核实事实

- 当前分支为 `dev`，相对 `github/dev` ahead 3；开始时只有未跟踪的 `output/`，本任务不读取、清理或提交该目录。
- 学生主导航由 `StudentNav.vue` 渲染五项：课堂、任务、学情、知识、答疑；`StudentPrimaryRoute` 同时把五个页面视为一级路由。
- 教师工作区已有四项：工作台、报告、问题、PBL；移动端为底部导航，桌面端为左侧导航，切换使用同页 `v-show` 保存状态。
- `pages.json` 使用 uni-app 原生导航栏。多个页面又在正文首屏显示同义大标题和英文眉题。
- 教师 PBL 首屏会连续出现“教师工作台”“PBL 教学助手”“PBL 教学工作区”；学生 PBL、学情和病例资源页也存在原生标题与正文 Hero 重复。
- 学生学习页同时承载 PBL 任务、个性化计划、知识巩固、能力画像、通知和病例入口；原“任务”和“知识”一级入口职责交叠。
- 页面跳转已集中在 `src/platform/navigation/index.ts`，页面没有直接调用 uni-app 跳转 API；一级页面使用 `reLaunch`，详情页使用 `navigateTo`，连续训练使用 `redirectTo`。
- T16 不需要修改 feature port、API/Demo adapter、OpenAPI、数据库、权限或存储。

## 主要问题

1. 五项学生底部导航在窄屏上压缩标签和触控区域，且“任务/知识”不是同一层级的互斥目的地。
2. 页面名被原生栏和正文重复表达，说明性 Hero 把当前任务挤出首屏。
3. 训练资源把知识地图、病例、讨论题和其他练习同时铺开，页面长且缺少明确入口语义。
4. 部分二级入口仍以一级切换方式打开，返回父页面的层级不够稳定。
5. 教师导航标签偏向数据对象，未直接表达“待办、学情、内容”的工作意图。

## 兼容与风险

- 页面路径保持不变；`studentCases` 只改变层级和打开方式，旧 URL 仍可访问。
- 教师 `tab=overview|reports|problems|pbl` 查询参数保持不变。
- 原生标题栏在 H5 与微信的高度、返回按钮和安全区行为不同，视觉验收必须覆盖两端构建。
- 训练资源使用 URL `view` 参数保存当前分组，未知值必须回退 `cases`，不能导致空白页。
- 移除可见正文 H1 后须为页面根节点提供可访问名称，不能只依赖视觉原生栏。
