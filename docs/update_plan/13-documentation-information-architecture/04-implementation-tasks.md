# 实施任务

## 阶段一：计划门禁

1. 记录工作区既有改动和引用范围。
2. 创建本目录，明确目标架构、文件映射、验证和回退。
3. 执行 Markdown 格式、相对链接、尾随空白和工程 skill self-check。

出口条件：计划与现状分离，所有映射都有唯一目标，计划门禁通过。

## 阶段二：建立新的当前文档入口

1. 建立 `product/`、`frontend/`、`backend/`、`operations/`、`governance/` 和 `records/` 目录。
2. 使用 `git mv` 移动映射中的当前和阶段资料。
3. 为前端、后端和运行目录新增简短入口页。
4. 将 `docs/README.md` 收敛为分组导航，保留架构、数据层、ADR、OpenAPI 和更新计划的直接入口。

出口条件：根目录只保留跨模块文档和总入口；当前文档与历史材料分层可见。

## 阶段三：统一早期工程计划目录

1. 建立 T01–T07 的独立目录，各自包含 `README.md` 和 `deliveries/`。
2. 将跨任务总任务书、执行状态和阶段交付记录放入同级 `01-07-engineering-governance/`。
3. 用新的 `docs/update_plan/README.md` 索引 T01–T13 与共享工程治理入口。
4. 更新 `AGENTS.md` 和 ADR 中的计划、交付证据路径及通用交付位置说明。

出口条件：更新计划根目录只有独立目录；T01–T07 与 T08–T13 使用同一层级和交付结构。

## 阶段四：链接、格式与交付

1. 更新所有已识别的相对链接，搜索旧路径并处理剩余引用。
2. 执行 Markdown 格式、尾随空白、链接解析、Git 补丁检查和工程 skill self-check。
3. 记录命令、退出码、未执行项、风险和回退。

出口条件：所有仓内相对 Markdown 链接存在，未修改运行时代码或受管配置。
