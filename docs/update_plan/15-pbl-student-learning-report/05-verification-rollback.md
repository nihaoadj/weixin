# 验证与回退

## 分阶段验证

- 数据：评价历史首轮不被覆盖；相同 plan/轮次幂等；计划状态、任务激活、评价和通知同事务。
- 报告：六种状态、多个计划、无参与但有全班任务、个人薄弱点频次和确定性下一步。
- 隐私：跨学生详情 404；课堂共同任务不暴露来源学生；响应无答案、rubric、隐藏事实、provider 或完整消息。
- 历史：自动记录可证明重建，人工结果只标 legacy；dry-run、apply、备份和 downgrade 保护。
- 前端：主导航迁移、两级页面、文本化图表、键盘、320～1440、loading/error/empty。
- E2E：讨论渐进报告到首轮 improved；首轮失败到第二轮通过或耗尽；API/Demo 合同一致。

## 最终门禁

执行契约生成与检查、数据库安全/迁移、后端完整检查、前后端边界、格式、Lint、类型、单测、H5/微信构建、API/Demo E2E 和工作树秘密扫描。所有结果写入交付记录，不以跳过或降级配置伪造通过。

## 回退

- 回退应用前停止 PBL 消息、采用发布、任务提交和病例评估写入，并生成一致性备份。
- 尚无评价历史时可 downgrade 0019 后回退应用和生成合同。
- 已有评价历史时 downgrade 必须拒绝；使用保留 0019 的兼容读版本，或从已验证备份恢复。
- 历史脚本 dry-run 不提交；apply 失败整体回滚且不覆盖备份。

## 外部验收

真实微信真机、生产数据回填、真实 Coze schema v3、医学专家审核和生产部署不在默认授权范围。完成仓库内门禁后仍只声明仓库内完成。
