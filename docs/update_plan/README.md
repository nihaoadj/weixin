## 1. 更新目标与边界

在保持现有微信小程序、H5、API/Demo 功能与数据兼容的前提下，完成以下更新：

1. 自动化测试与真实开发数据隔离，数据库迁移可验证、可恢复。
2. 本地和 CI 使用一致、可重复的质量检查；不合格变更不能进入受保护分支。
3. 前后端按业务分包、包内分层，落实依赖方向和模块公开接口，而非只移动文件。
4. 关键认证、授权、训练、报告、AI 失败路径有行为测试和独立覆盖率门槛。
5. 凭据、角色、敏感数据、依赖和发布配置形成有证据的安全控制。
6. 文档、AGENTS.md、项目 skill 与真实代码和检查命令一致。

本轮不引入微服务，不切换前端框架，不重做 UI，不新增医学业务，不把 Demo 扩展为与 API 完全等价的后端，不直接迁移生产库到 PostgreSQL，不进行生产部署或未经授权的远程历史重写。发现确需变更外部接口或业务政策时，先记录兼容方案和影响，再由项目负责人确认，不得夹带在结构重构中。
