# 实施任务与出口条件

> T09 锁定更新：实现顺序为知识目录 → PBL 模块/迁移/授权 → 固定 Coze SDK 与三 adapter → 事务外多轮推理与 revision → content 发布桥接 → `features/pbl` API/Demo → 契约和交付。application 只依赖 `PblInferenceGateway`，不得导入 SDK、`httpx` 或供应商 DTO。

以下任务均为待实现目标。实施者须先重新记录当时工作树和当前合同，不能以本文中的拟议路径冒充已落地事实。

## M01：冻结教学诊断合同

- 与病理学教师确认知识点目录、诊断推理阶段、问题类型、证据充分标准和建议题最低字段。
- 明确 Coze 智能体/工作流的输入输出 schema、版本、数据地区/保留策略和医学审核责任。
- 产出 Pydantic/TypeScript 领域合同及正反例，不包含供应商 DTO。

出口：PBL-02、PBL-03 可由确定性 fixture 验收，隐私和医学边界有责任人确认。

## M02：课堂会话与授权路由

- 建立 PBL session 与 conversation、student、teacher/class、pathology topic 的持久化关系。
- 后端 application 二次校验学生 owner 和教师 scope；定义教师队列读取策略。
- 补 Alembic 迁移、唯一约束和并发测试。

出口：学生消息能可靠路由到唯一教师范围，越权请求稳定返回 403/404。

## M03：Coze 服务端适配

- 实现专用 Coze gateway、受管配置和结构化输出校验；前端只调用本项目 API。
- 对必要历史做去标识化和长度/条数上限；补超时、限流、坏结构、重试、fallback 和日志脱敏测试。
- 更新部署/安全文档及 `.env.example`，但不写入真实凭据。

出口：mock 合同测试覆盖全部失败类别；经授权的测试环境证明真实 Coze 成功链路，且无客户端密钥。

## M04：多轮诊断与建议题持久化

- application 决定 `probing` 或 `ready` 状态，并只接受 schema 合法的 Coze 候选。
- 保存诊断快照和教师建议题，建立薄弱处到题目的明确关联。
- 保证重复模型回调/客户端重试不会重复创建队列项。

出口：无充分证据不生成建议题；ready 结果在同一授权边界内可稳定重放和查询。

## M05：教师采用发布

- 增加教师建议队列、详情、编辑、拒绝和“采用并发布”交互。
- 通过 content 公开合同创建/发布正式问题，保存 `suggestion_id → problem_id` 关系。
- 对双击、超时重试、并发采用和中途失败进行事务/幂等处理。

出口：一次操作发布且重复请求不重复出题；目标学生可见，非目标学生不可见。

## M06：学生端 PBL 交互

- 区分普通医学问答与绑定课堂的 PBL 会话，展示 AI 追问、证据不足/已形成建议/服务不可用状态。
- 对话保存和重连不丢 session、诊断状态或 pending 请求；API 失败不回退 Demo。

出口：微信小程序和 H5 均完成 PBL-01～PBL-05 的可访问交互路径。

## M07：合同、回归与交付

- 同步 OpenAPI、生成类型、Zod mapper、API/Demo adapter、迁移和交付证据。
- 运行与改动范围匹配的边界、格式、Lint、类型、后端安全/迁移、契约、组件、API 和 E2E 检查。
- 单独记录真实 Coze、真机、合法域名、数据处理审批和生产配置等外部证据。

出口：PBL-01～PBL-07 全部有可追踪证据，无永久 skip 或仅日志告警的假门禁。
