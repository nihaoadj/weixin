# 产品与模块设计

## 单一学习流程

`选择班级/主题/沟通方式 → 四阶段证据 → 结构化诊断 → 教师采用发布 → 两轮巩固 → 自动判定 → 学情报告`

`guided` 与 `direct` 只是 participation 上不可变的回复策略：

- `guided`：以一条主要追问和必要脚手架推进当前阶段。
- `direct`：先解释学生问题，再提出一条与当前阶段对应的理解检验。
- 两者共用阶段、证据时序和 ready 门槛；不得仅凭学生提出问题认定薄弱点。

## 会话来源

- `classroom`：教师创建并绑定病例/目标；每名学生首次进入时选择自己的沟通方式。
- `student_initiated`：学生创建，必须绑定本人有效班级、选择同一主题下 1～3 个知识点；会话只对本人和班级 owner 教师可见。

单班级自动关联，多班级必须显式选择，无有效班级时不能创建。学生主动会话不进入其他学生的课堂列表，但诊断进入负责教师的现有 PBL 建议队列。教师仍可按现有规则发布给本人、指定本班学生或全班；无病例时不提供病例重练。

## 模块所有权

- `pbl`：统一 session、participation、消息、诊断、建议和学习报告；不新建平行业务模块。
- `classroom`：提供当前学生的有效班级摘要与既有 owner/member 判断。
- `content`、`learning`：继续通过公开 port 承担发布、任务和自动判定。
- `qa`、`reports`：仅维护旧自由问答与旧报告的只读兼容；新页面不再写入。
- `bootstrap`：继续是前端 API/Demo 唯一装配点。

## 前端体验

- 主导航为“研讨、学习、学情”；`studentPbl` 是唯一新会话入口。
- 新建主动会话时按顺序选择班级、同一病理主题下知识点、沟通方式和可编辑首问。
- 教师课堂首次参与只选择沟通方式；选择成功后进入统一消息流。
- 会话中显示来源、固定沟通方式、阶段、缺失证据、诊断和后续学习，不显示两套模式页签。
- 保留复制和继续提问；新会话移除旧客户端报告生成和手工加入复习。
- 旧 chat 深链带 conversation ID 时只读显示；无 ID 时转入研讨。旧历史可续开，但只传已确认主题和可编辑首问。
