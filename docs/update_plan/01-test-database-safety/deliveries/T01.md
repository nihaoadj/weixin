## 完成的步骤与验收 ID

### T01-01：启动时序与危险入口

pytest 的 `backend/tests/conftest.py` 在测试模块收集和应用导入之前创建随机、独占的临时资源，并在同一处覆盖 `DATABASE_URL`、JWT、AI/微信、seed 和 Demo 认证环境。根目录 `npm run backend:test`、`npm run backend:check`、`python -m pytest backend/tests`、`cd backend && python -m pytest`、单文件 pytest 均经过该入口；E2E 由 `scripts/run_e2e_server.py` 自己申请资源。

全仓扫描确认唯一的测试清表点是受管 fixture 中的 `Base.metadata.drop_all/create_all`；固定 `data/e2e.db` 删除路径已移除。生产/开发启动的 `backend/app/db.py` 仍保留正常应用行为，不由本任务执行破坏性操作。清表前后均有显式 `assert_owned_resource`，不以 URL 或 Python `assert` 代替所有权证明。

关键生命周期如下：

```text
pytest 进程
  -> conftest 导入（先申请临时目录/marker，再覆盖环境）
  -> 应用 Settings/engine 导入
  -> 每测：所有权校验 -> dispose -> drop_all -> 校验 -> create_all ->（可选显式 showcase seed）
  -> TestClient 上下文 startup/shutdown -> Session/engine dispose
  -> 成功退出才清理精确 marker 资源；失败/中断保留资源供诊断

Playwright
  -> E2E_API_PORT/E2E_H5_PORT 校验并传给后端/前端
  -> run_e2e_server 先校验端口和 CORS，再申请资源、head 迁移、显式 test seed
  -> uvicorn 退出 -> engine.dispose -> 校验后清理当前资源
```

### T01-02：导入前隔离与资源防误删

`backend/app/testing_resources.py` 提供随机临时目录、不可预测 token、JSON marker、规范化路径、父目录约束和精确 `app.sqlite3` URL。清理递归扫描所有条目，不跟随链接；拒绝根目录、数据库文件、marker、子项上的 Unix symlink、Windows junction/reparse point，包括悬空数据库链接；marker 必须是 JSON object 且 token 长度和内容匹配。

`conftest.py` 同时拦截 `socket.connect` 和 `socket.connect_ex`，只放行回环地址。外部继承的 SQLite URL 和任意 PostgreSQL URL 在子进程中都被临时 URL 覆盖，探针未触发外部连接。

### T01-03：统一 fixture 与全部测试迁移

移除 API、认证、性能、病例硬化/训练、数据层、个性化、第二阶段和种子测试中的手工 `setup_function` 清表。统一 `app`、`db_engine`、`db`、`client` 和自动 `managed_database` fixture；TestClient 使用上下文管理，保证 lifespan 和 engine dispose 被执行。需要展示病例的测试显式使用 `pytest.mark.seed_showcase`，不再默认注入。

### T01-04：E2E 端口、种子和资源隔离

`playwright.config.ts` 将 `E2E_API_PORT` 传入后端 `E2E_PORT`，将 `E2E_H5_PORT` 同时用于前端 webServer 和 `E2E_CORS_ORIGIN`；前端 `VITE_API_BASE_URL` 指向同一 API 端口。`playwright.demo.config.ts` 使用独立可配置 Demo H5 端口，Demo 保持纯前端模式，不伪造后端。

`run_e2e_server.py` 在创建资源前校验 API 端口和 loopback CORS 来源；迁移 head 后调用 `seed_test_data`，其中显式调用 showcase seed 并建立测试病例、用户、班级、报告等幂等样板数据。退出（包括 shutdown 文件）前调用 `app.db.engine.dispose()`，随后只清理当前 marker 资源。端口已占用时进程失败且不触碰已有监听者。
