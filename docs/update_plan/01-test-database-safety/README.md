# T01 测试环境隔离与数据库安全任务书

状态：阶段任务书。原始计划状态为“待执行”；实际仓库侧证据见 [T01 交付记录](deliveries/T01.md)。优先级：P0。执行角色：熟悉 pytest、FastAPI、SQLAlchemy、Alembic 的后端工程师。

## 1. 目标与交付边界

让任何受支持的测试入口都只能修改本次运行创建的测试资源；即使开发环境配置指向开发库，也不能因为测试导入应用而清空数据。统一 fixture，验证迁移，并使 E2E 支持不同运行互不覆盖。

本任务负责测试基础设施与数据库安全，不承担全部业务用例补测，不改变生产数据库结构，不对真实数据库执行恢复、迁移或清表。业务测试由 T05 扩展，数据库连接结构重构由 T04 在本任务的安全合同上继续实施。

## 3. 前置条件与交接

无其他开发任务的硬前置。先记录已有改动和测试使用的解释器；不要运行当前未修复的 `backend:test`、`backend:check` 或 `check:all`。

完成后交给 T02、T04、T05：安全 fixture/API、受支持入口清单、DB 安全测试、迁移测试命令、测试数据构造方式和已知限制。后续任何数据库生命周期重构都必须复跑本任务防护测试。

## 4. 目标设计

1. 在 pytest 收集业务测试、导入应用配置和创建 engine 之前完成环境隔离；不能依赖执行较晚的普通 fixture 才修改环境变量。
2. 每次运行分配不可预测、独占的临时目录；每个独立 worker/进程有独立数据库或明确的互斥策略。不要用文件名含 test、APP_ENV=test 作为唯一安全依据。
3. 清理操作只作用于测试启动器创建并登记的规范化绝对路径；验证所有权标记、预期父目录、连接 URL、符号链接或 Windows junction 等边界后才能删除。
4. 默认忽略测试进程继承的业务 DATABASE_URL，使用自建临时库。若支持显式测试库覆盖，只接受受管理的临时资源；外部库 URL 必须拒绝，不得尝试连接后再判断。
5. 统一管理配置缓存、engine、Session、应用 lifespan、依赖覆盖以及线程间连接，避免新配置与旧模块引用混用。
6. 测试结束先关闭 TestClient、Session 和连接池，再清理资源。失败或中断允许保留本任务临时目录用于排查，但不能扩大清理范围。

可选择文件型临时 SQLite 或正确配置共享连接的内存 SQLite；必须证明 FastAPI TestClient 的线程和多个会话使用同一测试数据库，而不是每线程空库。采用事务回滚 fixture 时，必须处理应用代码内部 commit，不能假设测试最外层 rollback 能撤销所有写入。

## 5. 分步实施

### T01-01 记录危险入口及受支持启动方式

列出根目录 npm 命令、backend 目录 `python -m pytest`、根目录 `python -m pytest backend/tests`、单文件运行、IDE pytest 和 E2E。标出每个入口的配置首次读取位置、是否加载 .env、是否启动 lifespan、数据库操作位置。

产出：启动时序图和危险操作清单。完成标准：测试目录、脚本及应用启动中的每一处破坏性数据库操作均有归属，不能只检查一个测试文件。

### T01-02 实现导入前隔离与安全检查

在最早加载的测试配置/启动器中创建临时环境；设置测试专用、足够长度的 JWT key，关闭真实 AI/微信调用和自动开发种子。确需 HTTP mock 的业务测试自行启用受控假服务。

建立独立测试 app/engine factory 或等价的安全机制，确保所有测试导入到的是隔离后的依赖。重置配置缓存应发生在受控生命周期内，不能修改开发服务器进程的状态。

加入数据库资源所有权检查，覆盖路径规范化、越界、已有文件冒用及重复清理。检查函数不得以真实开发库作为破坏性实验对象。

产出：启动器、受管资源工具、使用说明。完成标准：在模拟外部 DATABASE_URL 的子进程中测试启动安全，且连接外部地址的探针未触发。

### T01-03 统一 fixture 并迁移全部测试

建立可组合的 app、db、client、学生/教师/审核者 fixture。替换所有散落的 setup_function 清表，包括性能、种子、硬化及数据层测试中的手工清理。

生命周期不依赖测试顺序；使用上下文管理启动/关闭 TestClient，使 startup/shutdown 也被验证。默认不注入展示种子；需要种子的用例明确声明并验证幂等。

禁止简单地给所有测试加一个通用跳过条件，也不能通过全局关闭数据库完整性检查掩盖外键问题。先定位现有循环外键清表警告：优先用隔离数据库生命周期避免不可靠的清表顺序，只有可证明无害的警告可精确记录，不允许一律过滤。

产出：统一 fixture、已迁移测试、移除的重复逻辑清单。完成标准：单个测试、不同组合、全套、连续两次运行均互不污染。

### T01-04 隔离 E2E 与种子运行

将 E2E 固定数据库改为每次启动独占目录/文件，记录所有权。端口可配置；支持不同运行使用不同端口；占用时明确失败，不擅自结束已有服务或复用未知服务。

启动子进程前显式设置 APP_ENV、数据库、JWT、AI、展示种子和演示认证配置，禁止意外继承本地真实 AI 配置。清理只处理当前启动的进程和数据库。

开发 seed 脚本继续保留非生产保护与幂等性。E2E seed 必须指向受管测试资源，不利用开发库来节省初始化步骤。

产出：启动/退出逻辑、Playwright 参数衔接、两个独立运行的证据。截图与浏览器环境标准由 T02 负责，业务流程由 T05 负责。

### T01-05 完善迁移与数据保留验证

读取实际 Alembic revision 图，确认只有一个有效 head。编制时存在工作区 `20260830_0009`，不能只测试旧的 0007/0008，也不能因其未跟踪而擅自删除。

在临时数据库中覆盖：空库到 head；0004 旧数据到 head；0008 到 0009 的用户认证来源、报告 reviewer 字段；重复 upgrade；支持的 downgrade 后再 upgrade。涉及删除新列的 downgrade 必须明确数据损失范围，不能宣称全部数据无损。

比较关键记录、索引、唯一约束与 schema；明确初始迁移引用当前 metadata 的历史风险，禁止为此次目录重构大规模改写已发布 revision。需要新增修复迁移时单独记录原因和兼容性。

产出：迁移矩阵、可重复测试、临时库备份恢复演练。PostgreSQL 兼容性未实际测试时标记未验证，不能根据使用 SQLAlchemy 就承诺直接切换。

### T01-06 接入安全命令并交付

实现 `backend:test:safety`、`backend:test:migrations`，使 `backend:test` 与 `backend:check` 默认进入隔离环境。与 T02 顺序集成 package.json；将安全 fixture 的使用和失败诊断交给 T07 更新正式文档。

## 6. 必须完成的验收矩阵

| 验收 ID | 方法                                                                   | 期望结果                                                       |
| ------- | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| DB-01   | 在临时目录建立模拟开发库及哨兵行，继承该 DATABASE_URL 后启动测试子进程 | 模拟开发库行、schema、文件内容不变；测试使用不同数据库         |
| DB-02   | 传入任意外部数据库 URL，拦截连接函数观察是否调用                       | 拒绝或安全覆盖；外部连接调用为零                               |
| DB-03   | 在临时沙箱构造越界、符号链接/junction、伪造文件名                      | 清理拒绝越界，不碰沙箱外资源；平台不支持链接时明确记录替代验证 |
| DB-04   | 单文件、全套、改变测试顺序、连续运行两次                               | 结果一致；不存在跨用例残留                                     |
| DB-05   | 两个 pytest/E2E 运行使用独立资源同时启动                               | 数据互不覆盖；冲突的端口只导致清晰失败                         |
| DB-06   | 触发应用内部 commit、异常及 lifespan                                   | 测试之间仍隔离；连接正确关闭                                   |
| DB-07   | 空库、旧库、当前 head 升降级矩阵                                       | 预期数据/索引保留；允许的数据损失清楚声明                      |
| DB-08   | 测试运行中途失败/中断                                                  | 只留下或清理本次资源，原有文件及进程不受影响                   |
| DB-09   | 不提供真实凭据并拦截非本地网络                                         | 单元/集成测试不访问真实 AI、微信或其他外部服务                 |

所有破坏性负向测试都使用新建的模拟资源，禁止拿用户真实 dev.db 验证防护。

如新 fixture 导致业务测试不稳定，先在临时资源上定位连接共享、commit、lifespan 和种子顺序问题；不可回退成对开发 engine 清表。必要时暂停依赖任务，保留安全启动防护并回退后续 fixture 优化。只回退本任务明确的提交，不恢复或覆盖用户原有开发数据库。不能以关闭外键、跳过失败测试或吞掉异常作为完成方式。
