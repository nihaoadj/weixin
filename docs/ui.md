# UI与交互规范

界面突出教学证据、来源身份和下一步操作。业务见[产品](product.md)，渲染检查见[微信验收](wechat.md)。

## 页面、模块、记录、字段

教师记录详情采用四级层次：页面 → 模块 → 记录 → 字段。原生导航承担页面标题，正文围绕当前任务，不重复大hero或装饰性入口区。

异质业务模块使用一层surface、1px边界、小圆角、24rpx内边距及24–32rpx模块间距，不加阴影；顺序为标题、必要说明/状态、正文、动作。模块间距至少是内部普通段落间距的1.5倍。每页最多一个最强焦点模块，可用克制的4rpx品牌边标识。

同类记录在模块内使用18–22rpx垂直留白、轻分隔线、对齐的标题/元数据/状态/动作，不给每条记录套卡。字段采用弱标签/强值的定义网格，窄屏单列；表单始终保留可见标签、相邻说明和动作前的错误。相邻文字角色至少在字号、字重、色彩或位置两项有区别。

学生证据中性，系统判定为有标签的结构化摘要，AI参考按场景标明教师待审或“AI生成·未经教师审阅”，教师编辑形成独立编辑面和唯一主要动作。AI建议不套教师草稿样式或错误警告色。卡片用于独立操作、可聚焦对象或确有边界需要的信息。

## 共享视觉与页面特点

先检查`src/uni.scss`、`src/App.vue`和共享组件的现有语义token，复用颜色/间距/排版；继承样式导致问题时修正受影响消费者，避免改全局污染另一角色。教师临床色系使用现有--med变量，页面浅背景、白surface、深墨文本和克制的青绿品牌色；token取值以代码为准。

学生主题限定作用域，保留深蓝文本、青蓝动作与白色连续AI回复；不能把AI文本重新切成重复卡片。学生消息、私人续问和AI回复身份可辨，输入框左侧的逐消息回应方式切换保留草稿和键盘状态。知识树来自真实节点/边，聚焦视野外前置必须可见，不添装饰性依赖。

教师主导航为 PBL、学情、内容，原三个根地址承载同一个连续切换容器；横向及底栏切换改变当前正文，不重新打开根页。各工作区保留独立筛选，学情三个正文共享班级/课堂/日期，只有当前面板保存面板偏好；详情携带所属上下文，原生返回恢复容器当前项，无栈回所属根入口。教师默认PBL，旧入口继续规范化。顺序为PBL、总览、知识与推理、学生、内容，相邻真实正文先挂载并完成初始化，再允许横向切换。当前页与目标页同位移连续移动，底栏固定，学情页签背景随进度移动；慢划需视口22%且至少60px，快划需32px及0.5px/ms，松手240ms完成或回弹。未准备好的目标不让当前正文先滑走；底栏原生tap与正文索引共用Deck状态，选中图标/文字同步更新；底栏和页签点击直接激活目标并结束原手势/动画，不等待ready或跨层自定义事件，目标未初始化时显示其原有加载/错误状态。点击不横跨中间空位置，底栏点击学情始终进入总览；显式面板入口与横向切换保留指定面板。纵向、多指、长按、取消、原生返回边缘及日期弹层保留原交互；动画期间忽略重复横向手势，点击可中断动画切换；卸载取消定时提交，平台支持减少动画偏好时关闭过渡。

PBL 根页只围绕课堂列表与阶段看板组织，不设测试待处理分栏。学生记录分别进入“查看固定诊断”的只读研讨分析和“查看最终测试”的审阅处理；跨课堂测试待办由课堂下拉菜单进入独立二级列表。旧队列地址兼容到该列表，详情返回保留合法班级、课堂及队列类别。固定诊断是审阅依据，不显示退役审批状态为当前待办，创建与关闭留在课堂，成绩分析跳转学情。学情独立选择班级、课堂、日期和面板，说明进度、完成成绩与诊断的不同口径；仅只读结果详情按需展示完整作答。内容仅显示病例库、个人题库两项，按普通列表搜索、查看/编辑和删除，不提供生命周期状态筛选或病例医学审核入口，不再展示重复的最近发布、讨论题、知识卡或历史补卡。学生首页知识点学习进入知识节点/图谱，病例页只保留独立病例与知识图谱；旧复习和问题详情仅作有效页面跳转。筛选反馈、原生picker标签和分页保持一致；仅有多页时展示分页，端点正确禁用并保留筛选，不发明计数、审核结果或诊断。

学习流程使用计划列表、计划详情、资料阅读、AI病例、最终测试和学习结果六个详情入口。计划详情将可变数量的资料/病例资源排成顺序路线，最终测试固定为最后一步，进度同时统计资源与已提交测试。资料连续阅读，病例保持连续对话；学习阶段只表达进度，不显示分数。测试整份提交前不展示答案，未交成绩显示未有数据；新试卷纵向完成3单选、1多选、1简答，提交后待模型按冻结要点完成简答评分。结果页上部一次聚焦一题并左右切换，长题在题卡内滚动；下部共享一条整卷导学对话，学生与AI消息按研讨式身份排布并在固定区域独立滚动，输入栏留在底部。切题仅改变下一条消息的题目锚点。等待教师、生成失败、待判分、失效课堂有具体下一动作。教师在同一固定分析中处理测试草稿，开放后只读，题库副本编辑与开放动作分别呈现。

PBL 根页按用户指定的 `10-PBL首页最终版.png` 局部覆盖通用视觉规则：冰蓝波纹 hero、深蓝文字、并排班级/课堂选择、四项真实统计、两列白色圆角学生卡、蓝/青描边动作及青绿完成标识。新建、关闭课堂与跨课堂测试队列收进课堂菜单，列表只展示研讨完成学生，进行中人数仅出现在统计栏；卡片发布标签表示学习路线状态。其他页面正文沿用现有设计。

PBL根页固定在视口内，hero、筛选、四项统计、“研讨完成学生”标题及底栏不随列表滚动；标题前加青色圆角竖标。默认8条按两列四行组织，顶部适当收紧；渲染后测量学生区域实际高度，用网格最小高度和等比例行高分配四行卡片，卡片内边距恢复16rpx，均匀利用剩余空间，目标为第四行按钮完整位于底栏上方且不留下大块空白。查看更多存在时预留44px，展开后恢复自然长列表；测量失败保留紧凑布局，长姓名不限制高度。四项统计数字在各自文字区域居中，两侧选择框采用一致的60rpx最小高度/8rpx垂直内边距，描边下拉箭头几何居中。只有学生区域原生scroll-view滚动，查看更多动作在该区域内，切换班级/课堂重置滚动并重新测量；新建表单也在固定区域内独立滚动。

教师学情根页按 `ui参考图/学情/02-学情-最终参考-01/02/03` 三图局部覆盖通用视觉：浅冰蓝波纹与医学书本插画、黑色系标题/正文/姓名与中性灰标签、蓝色数据（低分仍橙红）、青绿渐变选中项、白色圆角卡片与细浅蓝分隔线。总览为环形完成率/区间平均分、知识表预览、低分学生；知识与推理为完整知识表和可展开诊断组；学生为统一浅蓝人形头像的两行列表，第一行姓名/平均分徽标/箭头，第二行批次测试比例与研讨次数，继续加载保留已有行。学生页顶部、筛选、页签、卡片标题及底栏固定，只有学生记录卡片内的列表独立滚动；首屏按实测可用高度均分整数个正常学生行，避免末行标签被裁切，激活/筛选/窗口变化后重新测量，长内容可自然扩展；卡片与底栏之间保留冰蓝留白，统计标签等宽，范围变化重置列表滚动位置。总览固定一屏，不滚动；知识与推理保持外层滚动。主界面只保留三页签、并排班级/课堂，日期与口径收进顶部副标题弹层。知识低于60%橙红、学生低于60分浅红徽标，null显示暂无样本/结果，真实0保留。只影响学情，宿主状态栏/导航/安全区不重复绘制。

## 交互与可访问性

动作文字具体且与待处理/成功状态一致。异步操作有pending、防重复、可恢复错误及成功去向；失败保留输入。空状态说明原因和下一有效动作，缺失分数显示未有数据，不以0或合成活动填充。发布/删除/医学相关操作明确范围和后果，

使用系统中文字体，无需远程字体或装饰图片。触控目标实际至少44px，主要提交48px；窄屏元数据至少12px，普通文本对比度4.5:1，状态不能仅靠红绿表达。优先原生控件，确认实际输入的标签、选中状态、焦点与错误关联，不只检查uni-app模板ARIA。

微信viewport使用100vh；固定栏、键盘和安全区域不遮内容或焦点，长文可滚到底完成操作。宽屏改善比较和上下文，不只是放大rpx；详情内容最大宽度遵循现有920px限制。加载/媒体预留尺寸，长列表先评估性能；动效表达状态变化并尊重减少动画设置。

## 验收关注点

学情总览的学习概况收紧为约240rpx，保留环形、平均分与两条数量统计；完成率数字26rpx、百分号20rpx，居中于圆环内，兼容小数、100%与暂无样本。知识点预览最多4项，低分学生预览最多2名；总览整体固定一屏。总览学生行与学生页共用姓名/均分/箭头及两条等宽标签，预览行距更紧，分数徽标固定宽度以保持列对齐。知识与推理完整表格按真实知识点数量显示；知识缺口用青色填充文档图标，推理问题用橙色对话图标。收起态只在完整覆盖诊断组且全部摘要相同时显示共同摘要，否则显示查看提示。

按[微信验收](wechat.md#交互与渲染)检查改动可达的长文本、加载、空、错误、禁用、返回与窄屏状态。

## T64 内容直接维护

教师内容页使用固定主体，顶部插画、资源标签、搜索与创建区不随列表滚动，病例/题库列表仅在剩余高度的原生scroll-view内滚动；底部导航留在列表外且完整可见，不新增catchtouch拦截。教师内容保留病例库/个人题库两标签和搜索，不显示生命周期状态栏、状态徽标、审核、发布、归档或恢复操作。病例保存即可教学选用；病例详情/编辑及题库列表/详情只保留实际可用的查看、编辑、删除，删除一次确认，取消不写入，失败保留原记录并可重试。旧status查询/偏好忽略，返回保留资源类型与关键词。旧病例医学审核地址仅角色保护后回病例库，不再提供审批表单。个人题库仍从最终测试审阅页导入，不新增手动题库创建或组卷。
