# 07. 安全、隐私与合规

> 本文是产品与工程控制清单，不构成法律意见。上线范围、运营主体、用户年龄、模型供应商、数据存储地域和是否面向公众都会改变适用要求，应由专业法务和数据保护负责人确认。

## 1. 当前必须立即处置

1. 在模型供应商控制台撤销并轮换源码中出现的密钥；不要仅从 Git 最新版本删除，因为历史提交/构建包可能仍含凭证。
2. 检查该密钥的调用日志、费用、来源 IP 和异常用量，保留事件记录。
3. 暂停发布包含客户端直连模型和自选教师角色的版本。
4. 将所有模型访问迁入服务端密钥管理，限制环境、额度和可调用模型。
5. 检查已上传体验版/开发版是否可下载到包含凭证的包，按平台能力清理或失效处理。

## 2. 合规基线

### 2.1 个人信息与医疗健康数据

《个人信息保护法》将医疗健康信息以及不满十四周岁未成年人的个人信息列为敏感个人信息，并对特定目的、充分必要、严格保护和单独同意提出要求。参见[法律全文（国家市场监督管理总局）](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)。

对本项目的直接含义：

- 医学对话不能被当作普通聊天日志；
- 收集前要说明必要性、影响、用途、保存期限和接收方；
- 默认不收集真实病历标识，不把对话默认用于模型训练；
- 若用户可能低于 14 周岁，必须设计监护人同意与专门规则；
- 对敏感个人信息、委托处理、自动化决策等高风险活动开展个人信息保护影响评估并留存记录；
- 提供查阅、复制、更正、删除、撤回同意和注销渠道。

### 2.2 网络数据安全

[《网络数据安全管理条例》](https://xzfg.moj.gov.cn/front/law/detail?LawID=1734)要求建立管理制度，并采用加密、备份、访问控制、安全认证等措施；对委托/提供数据也要明确处理目的、方式、范围和安全义务。

项目需要：数据分类分级、供应商数据处理协议、访问审计、备份恢复、漏洞处置和安全事件预案。不能只依赖云平台默认安全。

### 2.3 生成式 AI 与内容标识

[《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)涉及适用人群/用途公开、输入与使用记录保护、内容安全、投诉举报和备案/安全评估等要求。是否属于向境内公众提供服务、是否仅限机构内部教学，会影响具体适用性。

截至本文基线日期，还应评估：

- [人工智能生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)：AI 文本界面和导出内容的显式/隐式标识；
- [已备案/登记服务公告](https://www.cac.gov.cn/2026-03/17/c_1775482074695536.htm)：通过 API 调用已备案模型后的应用登记和公示要求；
- [人工智能拟人化互动服务管理暂行办法发布说明](https://www.cac.gov.cn/2026-04/10/c_1777558395023172.htm)：模拟患者/AI 导师的拟人化互动、未成年人、生命健康和安全管理要求；
- [“人工智能+医疗卫生”实施意见](https://www.nhc.gov.cn/guihuaxxs/c100133/202511/d1a42ae835c743b9b3e83ac0253c3e9f.shtml)：安全可控、规范应用和医疗卫生行业治理方向。

### 2.4 运营前置判断

上线评审必须书面回答：

- 服务仅面向特定学校内部，还是面向社会公众？
- 用户是否包含未成年人、患者或医务人员？
- 功能是医学教学，还是已触及诊断、治疗建议、健康管理？
- 使用的模型是否完成适用备案/登记，应用是否需要登记、公示或安全评估？
- 数据是否离开中国境内，供应商是否保存输入或用于训练？
- 是否需要互联网信息服务、医疗相关或其他行政许可/备案？

## 3. 威胁模型

| 威胁 | 典型攻击 | 控制 |
| --- | --- | --- |
| 身份伪造 | 修改本地 `role/openid` 冒充教师 | 可信微信上下文、服务端 RBAC、教师邀请审批 |
| 越权访问 | 枚举 reportId 读取他人对话 | 资源级 scope 校验、不可预测 ID、统一 repository |
| 密钥泄露 | 解包小程序获取模型密钥 | 服务端 Gateway、密钥管理、轮换和用量限制 |
| 提示注入 | 学生输入要求泄露系统提示/他人数据 | 不可信内容隔离、最小上下文、工具白名单、输出检查 |
| 数据外泄 | 日志记录完整医疗对话或供应商留存 | 日志脱敏、最小化、合同约束、地域与保留控制 |
| 重放/重复提交 | 重复请求生成多份报告/多次计费 | 幂等键、请求哈希、状态机、事务 |
| 数据篡改 | 客户端提交分数、状态、userId | DTO 白名单、服务端计算、条件更新、审计 |
| 供应链 | 依赖包恶意/漏洞 | lockfile、审计、最小依赖、构建来源验证 |
| AI 误导 | 危险用药或延误急救 | 风险分流、固定安全响应、RAG、医学评测、人工复核 |
| 内部滥用 | 管理员批量浏览健康对话 | 职责分离、按需授权、敏感访问告警、审计抽查 |

## 4. 认证与授权

### 4.1 认证

- 云函数从可信平台上下文读取微信身份，忽略客户端同名字段；
- openid 只用于身份映射，不作为对外业务 ID；
- 管理后台使用独立强认证和 MFA；
- 账号冻结、删除、角色撤销要在下一请求立即生效；
- 不在日志、URL、页面参数或统计平台发送 openid/session key。

### 4.2 授权

授权决策：`actor role + scope + resource ownership + resource state + action`。

例如教师读取提交需同时满足：

```text
role_binding(role=teacher, courseId=X, active)
AND submission.assignment.courseId = X
AND submission.status allows read
```

页面隐藏按钮不构成权限控制。所有云函数、批量导出、定时任务和后台工具都要走相同的策略层。

## 5. 数据保护

### 5.1 数据最小化

- 微信头像/昵称不是使用医学练习的必要条件时，应允许跳过；
- 不收集身份证、手机号、真实病历号、精确位置，除非有独立明确用例；
- 自由问答前提醒去标识化；可在服务端识别并遮蔽明显标识符；
- 给模型的上下文只包含完成当前任务所需消息，不默认发送完整用户历史；
- 观测日志保存 ID、耗时、状态和分类标签，不保存完整正文。

### 5.2 加密与密钥

- 传输使用 TLS；禁止明文 HTTP；
- 云数据库、备份、对象存储使用平台静态加密能力；
- 高敏字段按风险采用应用层加密/令牌化；
- 密钥按 dev/staging/prod 隔离，最小权限、定期轮换、到期提醒；
- 密钥不得进入 Git、客户端、错误响应、截图、日志和工单。

### 5.3 保留与删除

建立数据保留表：数据类别、目的、法定/业务依据、期限、归档、删除方式、责任人。到期任务必须可观测并输出删除证明。

用户删除请求的范围应覆盖：

- 主数据库与文档正文；
- 搜索/向量索引；
- 缓存和导出文件；
- 模型供应商侧按合同可删除的数据；
- 备份随保留周期自然淘汰，期间禁止恢复后重新上线已删除数据。

审计/法定义务要求保留的最小记录应与业务正文分离，并在隐私说明中披露。

### 5.4 第三方模型

上线前完成供应商评估：

- 运营主体、服务地域和子处理者；
- 输入/输出是否保存、保存多久、是否用于训练；
- 数据删除、导出、事件通知与审计能力；
- 模型备案/登记、公示信息和内容安全能力；
- SLA、限流、停服、模型变更通知；
- 合同中的保密、知识产权、责任、跨境和安全条款。

若供应商策略不允许处理真实健康信息，Gateway 必须阻止发送，而不是只写免责声明。

## 6. 日志与审计

必须审计：

- 教师角色授予/撤销、班级成员变更；
- 题目审核、发布、撤回；
- 学生提交、教师评分、反馈发布和版本冲突；
- 敏感数据查看、导出、删除；
- 模型/提示词/知识库/安全策略配置变更；
- 高风险安全事件与人工处置；
- 管理员登录、失败和异常批量访问。

审计日志应防篡改、访问隔离、保留明确；记录变更摘要，不复制完整医疗正文。敏感查看可触发实时告警。

## 7. 安全开发生命周期

| 阶段 | 必做 |
| --- | --- |
| 设计 | 威胁建模、数据流图、影响评估、权限矩阵 |
| 开发 | schema 校验、参数化访问、secret scan、依赖锁定 |
| 评审 | 权限/数据/AI 安全专项 checklist |
| 测试 | 越权、重放、注入、隐私泄露、紧急风险、供应商失败 |
| 发布 | 生产包扫描、配置差异、最小权限、备份与回滚演练 |
| 运行 | 漏洞管理、密钥轮换、访问复核、事件演练、合规更新 |

## 8. 安全事件响应

建立联系人与分级：

1. 检测与确认：requestId、受影响环境、数据类别和用户范围；
2. 遏制：撤销密钥、禁用函数/账号、限流、切断供应商；
3. 取证：保留审计与配置快照，避免在公共群传播敏感数据；
4. 修复：补丁、轮换、恢复和回归测试；
5. 通知：按适用法律、合同和主管部门要求通知受影响方/监管；
6. 复盘：根因、时间线、控制缺口、责任人和完成期限。

至少演练：模型密钥泄露、教师账号被盗、跨班级越权、敏感对话误传第三方、错误模型版本产生危险建议、备份恢复。

## 9. 上线安全门禁

以下任一项不满足即 No-Go：

- 仓库和生产包中发现有效密钥；
- 客户端可控制身份、角色、分数或资源归属；
- 未完成敏感个人信息告知/单独同意和删除流程；
- 紧急医疗风险测试未通过；
- 模型供应商数据用途/保存/备案状态未确认；
- 无审计、备份、恢复或安全事件联系人；
- 未完成越权测试和生产权限复核；
- 法务/医学/安全负责人未签字。
